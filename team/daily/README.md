# Утренние посты: «Начало игрового дня» и «Итоги вчерашних ставок»

Просьба владельца: каждое утро около 06:00 МСК ему в личку бота приходят два готовых поста с кнопками
«Опубликовать» / «Редактировать» / «Не надо», а перед ними одна служебная строка «Утренние посты на 16 октября —
проверьте и опубликуйте». В канал сами ничего не публикуем. Тексты пишет скрипт, без LLM: одно задание Actions в день.

1. **Начало игрового дня** (`ММДД-m1`): приветствие, какой сегодня день (сколько матчей КХЛ сегодня и НХЛ ночью,
   окно начала по МСК, дерби или встреча лидеров НХЛ, день недели), при некоторых подачах список матчей
   («12:30 Адмирал — Спартак»), призыв подумать, куда заходить, иногда «прогнозы — позже». Последняя строка:
   `#кхл #нхл`, только лиги, которые играют.
2. **Итоги вчерашних ставок** (`ММДД-r1`): опубликованные владельцем прогнозы, у каждого счёт и вердикт
   **ЗАШЛО** / **МИНУС** / **ВОЗВРАТ**, итог «3 из 5», единицы при ставке в 1 ед. (если известны кэфы), счёт недели
   (со среды; в понедельник «итог недели»), спокойная концовка по тону дня. Без #итоги: только `#кхл` / `#нхл`.
   Если матчей не больше 8, пост уходит фото с подписью: карточка «Итоги прогнозов» (`card.py`, 1080 px, в стиле
   «Итогов дня» `render/matchday_vs.py` results). Подпись длиннее 1024 знаков: сначала строки матчей становятся
   компактнее, если и так не влезает, то пост идёт текстом, а карточка отдельным постом `ММДД-r2`.

Правила канала соблюдает `compose.validate` (проверяется перед отправкой, нарушения пишутся в служебную строку):
эмодзи нет; нет «Джарвис», букмекеров, промокодов, «гарантий» и слова «таблица»; теги Telegram закрыты; длина в пределах;
**в первой строке нет «число месяц + ЧЧ:ММ»**. Бот (`teamEditStart_` в `apps-script/project/Код.js`) по такой строке
поставил бы пост на выход «за 1,5 часа до матча», а утренние посты должны выходить сразу.

## Как запустить

```
python3 team/daily/morning.py --job 2026-10-17     # заготовка team/out/2026-10-17/morning.json
git add team/out/2026-10-17/morning.json && git commit -m "Утренние посты 17.10" && git push
# itogi.yml, ref claude/project-migration-old-account-6e31vz,
# payload {"kind":"team","job":"team/out/2026-10-17/morning.json"}
```

В Actions `render/team_job.py` запускает make `team/daily/morning.py 2026-10-17`. Скрипт загружает расписание и счёт,
пишет сообщения в `messages` того же задания (team_job перечитывает их после make) и рисует карточку в
`out/daily/<D>/recap.jpg`. В логе остаются строка `DAILY {…}` (подачи, сколько прогнозов, найденные проблемы) и строки `→ owner · …`.

Без сети и без записи:
- `python3 team/daily/morning.py 2026-10-17 --dry`: тексты в консоль (в сессии сеть к лигам закрыта: будет «не загрузилось»);
- `python3 team/daily/morning.py --history 2026-10-17`: какие подачи и обращения выпали за неделю;
- `python3 team/daily/test_daily.py [--show]`: проверка расчёта ставок, разбора INBOX/SENT репозитория и 7 дней подряд на
  макете API (`DAILY_MOCK=<файл>` подставляет ответы API и в сам скрипт; `DAILY_NOW="2026-10-17 06:05"` задаёт «сейчас»).

Ключи: `--variant N` даёт другой вариант текстов дня (если владелец попросит переписать); `--no-card` отправляет итоги без
картинки; `--no-wait` не ждёт CUTOFF. Переменная `DAILY_CUTOFF=ЧЧ:ММ` меняет границу суток (по умолчанию 06:00).

## Откуда данные

| Что | Откуда |
|---|---|
| Матчи КХЛ сегодня, счёт и ОТ/Б | приложение КХЛ `khl.api.webcaster.pro` (`events_v2`, `event_v2`), как `team/picks/khl_data.py` |
| Матчи НХЛ ночи, счёт и ОТ/Б | `api-web.nhle.com/v1/score/<игровой день>`, как `team/picks/nhl_data.py`; лидеры: `standings/now` |
| Что опубликовано | `team/INBOX.md`: «опубликовано владельцем: ММДД-N», «… (по расписанию): ММДД-N» |
| Текст ставки и кэф | `team/picks/SENT.md` по номеру, сверху правки владельца из INBOX (см. ниже) |
| Прогнозы мимо бота | `team/PICKS.md` (строки без номера; «уточнить» не берём) |

**Правки владельца.** «правка владельца в боте: ММДД-N — …; Прогноз: …; Кэф: …», быстрые «прогноз → «…»», «кэф → …»,
«вернул прежний текст» меняют черновик. В канал попадает то, что было в черновике в момент публикации. Правка после
публикации меняет канал, только если в строке стоит «(и в канале)». Правку вида ««1,64» → «1,66»» и просьбу текстом
«поправить ММДД-N … заменить …» скрипт не разбирает и пишет владельцу «проверьте». Матч опубликован дважды (1510-2 и 1510-15):
в итоги идёт последний вариант, владельцу заметка.

**Ничего не опубликовано** на эти сутки: итоги строятся по отправленным владельцу (SENT.md, на матч последний номер).
Об этом сказано только в служебной строке, в самом посте нет. Счёт недели в этом случае не ставим.

**Какие сутки.** Итоги утра D включают прогнозы, чьи матчи закончились между CUTOFF дня D−1 и CUTOFF дня D (06:00 МСК).
Конец считаем по оценке: начало + 2:30, ОТ +0:15, буллиты +0:25. Получается КХЛ вчерашнего дня и НХЛ ночи с началом
до ~03:30. Матчи НХЛ с началом в 04:00–05:30 к 06:00 не доиграны и идут в итоги следующего утра, в отдельной группе
«НХЛ · ночь на 16 октября». Владелец видит их в служебной строке («В завтрашние итоги: …»). Так каждый прогноз попадает
в итоги ровно один раз, а перезапуск дня даёт тот же результат. Если задание запустили раньше 06:05, в Actions оно ждёт
(не дольше 35 минут; у itogi.yml предел 40). Поэтому запускать его нужно **не раньше 05:30 МСК**. Запуск раньше не
ломает итоги, но матч, который ещё идёт и по оценке должен был закончиться до 06:00, в итоги не попадёт, и владелец
увидит «Не вошёл: … не доигран». Хотите полную ночь НХЛ в одних итогах: `DAILY_CUTOFF=08:00` и запуск после 08:05.

## Расчёт ставок (`settle.py`)

В `team/picks/calc.py` расчёта ставок по счёту нет: там вероятности. Его рынки (`calc.markets`) используются как эталон
в проверке, где 729 сверок совпадают. Соглашения те же, что в таблицах и `team/picks/README.md`:
- победа / П1 / П2 / «не проиграет» (1Х, Х2) / фора / тотал / индивидуальный тотал считаются **по основному времени**, если
  в тексте нет «итоговая», «с учётом ОТ», «с ОТ», «включая ОТ»; «победа X» без уточнения тоже считается по основному времени;
- счёт основного времени после ОТ/Б: (меньшее, меньшее), потому что победа в ОТ/Б всегда на одну шайбу;
- целая линия (тотал 6, фора −1) при равенстве даёт **ВОЗВРАТ** с пояснением («ровно 6 шайб», «разница ровно в 1 шайбу»);
- экспресс внутри матча («П1 и тотал меньше 5,5», «1X + тотал больше 3,5»): минус, если не прошла хотя бы одна часть;
- линии ,25 / ,75 не разбираются, и владелец получает «посчитайте вручную».

## Чтобы посты не повторялись (`variety.py`, `texts.py`)

- **Шесть подач** у каждого поста: «список», «табло» (`<blockquote>`), «коротко» (2–3 строки), «рассказ» (абзац),
  «вопрос-ответ», «цифра дня» (первой строкой число). Подача не повторяется 3 дня подряд, а итоги в тот же день
  выходят не той подачей, что утро.
- **Банки фраз**: обращение (14: друзья, братва, ребята, мужики, хоккейная семья…; утро и итоги в один день с разными
  обращениями), приветствие, шапка, описание дня по ситуации (много матчей / обычный / только КХЛ / только НХЛ / мало
  матчей), большая ночь НХЛ, время КХЛ и НХЛ, дерби, день недели (понедельник, середина недели, пятница, суббота,
  воскресенье), призыв, «прогнозы будут», концовка, итог дня по тону (всё зашло / плюс / поровну / минус / ноль / одни
  возвраты), концовки по тону, единицы, неделя, возврат, вопросы для «вопрос-ответ». Ни одна фраза не повторяется
  7 дней. Проверка смотрит и на сами тексты: предложение без цифр и названий команд тоже не повторяется 7 дней.
- **Память без файла.** Выбор на день D полностью определяется датой: движок проигрывает календарь с 01.10.2026 и
  каждый день берёт фразы, которых не было в окне (случайно, но с зерном «банк + дата»). Поэтому история не хранится
  и не коммитится. У itogi.yml `permissions: contents: read`, так что Actions всё равно не смог бы её закоммитить, а из
  `team/out/*/morning.json` её не восстановить: в git лежит пустая заготовка, тексты появляются только в Actions.
  Перезапуск того же дня даёт те же тексты, пропущенный день ничего не ломает, `--history` показывает прошлую неделю.
  Цена: после правки банка на стыке возможен один повтор. Фразы опознаются по тексту, поэтому дописанная фраза
  не сдвигает остальные. `--variant N` меняет только этот день, а завтрашний пересчёт считает, что вышел вариант 0.
- Дописывать фразы — в `texts.py`. В банке должно быть не меньше фраз, чем дней в окне (обычно 8+). Подстановки
  `{…}` берите только из тех, что есть в этой ситуации (см. соседние фразы). Без эмодзи и без обещаний.

## Номера постов

`ММДД-m1` (утро), `ММДД-r1` (итоги) и `ММДД-r2` (карточка отдельно, редко). Бот принимает любой номер без «|»
(`tm|pub|<номер>`, `teamKbPid_` в `Код.js`), длина callback в пределах 64 байт. Буква в номере нужна, чтобы такие номера не
попадали под `\bММДД-(\d+)\b`: по этому шаблону `team/picks/check.py --next` выдаёт следующий номер прогноза, а итоги ищут
опубликованные прогнозы в INBOX. Числовой резерв вроде 1610-90 сдвинул бы `--next` на 1610-91.
`check.py` проверяет только задания с прогнозами, к morning.json его не применять.

## Файлы

- `morning.py`: запуск, окно итогов, сообщения задания, `--job`, `--history`, `--dry`;
- `data.py`: загрузка КХЛ/НХЛ в одном виде и макет `DAILY_MOCK`;
- `ledger.py`: INBOX + SENT.md + PICKS.md, т. е. что ушло в канал;
- `settle.py`: разбор текста ставки, расчёт, короткая запись («П2», «ТМ 4,5», «Ф2 +1,5»), падежи команд;
- `variety.py` + `texts.py`: движок и банки фраз;
- `compose.py`: подачи и проверка постов;
- `card.py`: карточка итогов;
- `test_daily.py`: проверки и макет API для примеров.
