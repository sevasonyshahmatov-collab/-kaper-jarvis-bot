# Рубрика «Экспресс» (владелец 31.10; с 01.11 — ежедневно)

Задача владельца: купоны из самых вероятных событий дня «в виде поста, и почему каждое событие должно зайти». Главное —
**шанс зайти, а не кэф**. Пока проба: черновики владельцу в бот, в канал и Instagram — только после его «да».

## Правила купона
1. **Нога** — исход с вероятностью модели **от 65 %** (первое число в строке «Что заходит» brief.md) и кэфом Pinnacle
   **1,20–1,65**; ноги отбираются по убыванию вероятности.
2. **Рынки и разнообразие (владелец 31.10): в купоне не больше одной форы.** Остальные ноги — индивидуальные тоталы
   команд (ИТБ/ИТМ), общий тотал, победа (в основное время / итоговая). 1Х/Х2 не берём. В НХЛ — «в основное время»,
   кроме пометки «с ОТ = осн. время на этой линии».
3. Из одного матча — одна нога; **матчи между купонами дня не повторяются**.
4. **Общий кэф** = произведение, до сотых: цель **1,80–2,00**, не жёстко — нет сочетания, тогда 1,75–2,05. Среди
   подходящих — наибольшее произведение вероятностей.
5. **Шанс купона = произведение вероятностей ног.** Владельцу честно сравнить с 1/кэф (обычно чуть ниже — маржа
   перемножается; 31.10: 52–53 % против 55 %) и назвать самую слабую ногу.
6. Всё это делает `team/picks/express.py` (константы P_MIN, K_MIN/K_MAX, TARGET/WIDE, MAX_FORA вверху файла).

Калибровка: отдельной проверки заходимости инд. тоталов у нас нет (31.10); общая заходимость прогнозов НХЛ 15–29.10 —
53 % при обещанных 61 % (`README.md` §3). Купоны — проба, итоги считать: `team/picks/EXPRESS_RESULTS.md` (завести с
первыми итогами: дата, купон, ноги, зашло/нет).

## Пост — всегда картинка + подпись (без картинки не присылать)
- Картинки: `render/express_card.py` (семья «Матчи дня»: тёмный фон, марка JARVIS | NHL / KXL / КХЛ · НХЛ, панели
  клубов, эмблемы, плашка «ставка · кэф», блок «общий кэф / шанс по модели»). `team/picks/express_render.py` рисует на
  каждый купон `e<k>_feed.jpg` 1080×1350, `e<k>_story.jpg` 1080×1920 (призыв «Разбор — в Telegram @jarvibet») и
  `e<k>_anim.mp4` (≤ 5 с: ноги выезжают по очереди, потом общий кэф). **Рисовать в Actions** — jpg/mp4 в `team/out`
  игнорируются git: первым шагом `make` задания.
- Подпись (≤ 1024 знаков вместе с тегами):
```
НХЛ · 31 октября – 1 ноября · экспресс
<b>Экспресс на три матча</b>

1. <b>Хозяева — Гости</b>, 23:00 МСК
ставка словами · 1,22
2. <b>Хозяева — Гости</b>, 1 ноября, 02:00 МСК
…

Общий кэф: <b>1,83</b>

<blockquote>По абзацу на ногу: «Команда.» и 1–2 предложения, почему зайдёт, — только факты из run (TEAM, LAST, H2H,
NHLSTAND, PER), от первого лица.</blockquote>

#нхл #экспресс #jarvibet
```
- Шапка: лига (НХЛ / КХЛ / «Хоккей» если обе / «Футбол»), даты матчей по МСК, «экспресс». Хэштеги: `#нхл` / `#кхл` /
  `#футбол` по лигам ног + `#экспресс #jarvibet`.
- **Строки «экспресс не зайдёт, если не сыграет хотя бы одно событие» нет** (владелец 31.10: аудитория в теме) — ни в
  подписи, ни на баннере.
- Проценты — только на баннере («шанс по модели», просьба владельца 31.10); в подписи процентов нет (правило 27.10).
  Без БК, промокодов, «верняка», гарантий. Тексты — через `ig-human`. Факты — `team/out/D/facts_express.md`.
- Кнопка «Опубликовать» в канал — после «да» владельца на формат (pid вида ММДД-eN). До тех пор — без кнопки.
- Свои файлы — `express_*`; номера ММДД-N и файлы одиночных прогнозов не трогать.

## Ежедневный запуск (задача 08:23 МСК → новый чат; шаги для холодного чата)
`D` — сегодня по Москве (`TZ=Europe/Moscow date +%F`). Работать в ветке команды `claude/project-migration-old-account-6e31vz`.
1. **Уже сделано?** `git pull --rebase`; если есть `team/out/D/express.json` и строка «экспресс» за D в `team/NOW.md`
   («События») — ничего не делать, одна строка руководителю. Оборванный запуск — продолжить с того, что есть в `team/out/D/`.
2. **Данные** (Actions, ~2 мин на лигу; README §1, «Логи Actions из облака закрыты»): по заданию на лигу —
   `team/out/D/express_khl_data.json`: `{"day": "D", "make": ["team/picks/notice_brief.py khl D"], "messages": []}`, так же
   `express_nhl_data.json` с `nhl` (в одном задании две лиги нельзя: у обеих пометки PB_1/N). Если утренние прогнозы уже
   собрали данные за D (`team/out/D/picks_khl_data.json` / `picks_nhl_data.json`, запуск success) — взять их run.
   Сборка — README §1 (`gh api …/check-runs/<job>/annotations` → `base64 -d | tar xz -C out/picks/<лига>-D`).
   НХЛ — игровой день D = матчи вечером D и ночью на D+1 по Москве.
   Футбол (если идёт проба `jarvis-picks-football`): строки FD* из запуска `foot_notice.py D` (пометки PB_ → `base64 -d |
   gunzip > out/picks/foot-D/fd.txt`). Нет данных какой-то лиги — без неё.
3. **Купоны:** `python3 team/picks/express.py --khl out/picks/khl-D/brief.md --nhl out/picks/nhl-D/brief.md
   [--foot out/picks/foot-D/fd.txt] --sizes 3,3,2 --out team/out/D/express_coupons.json` → 3 купона по 2–3 ноги.
   Прочитать вывод: нет купона — так и сказать владельцу, не натягивать. Матч начинается меньше чем через 2 ч после
   отправки — убрать его раздел из brief.md (копии) и пересчитать.
4. **Факты:** по каждой ноге из `brief.md` (TEAM, LAST, NHLSTAND, H2H, PER, NHLRATE) → `team/out/D/facts_express.md`
   с пометкой run; в LAST — проверить счёт в основное время (ОТ/Б: перед овертаймом была ничья).
5. **Тексты:** `team/out/D/express_<k>.txt` по образцу выше (k — номер купона), `python3 .claude/skills/ig-human/detect.py`
   и `humanize.py --report` — канцелярита и «структурных» замечаний 0 (тире и «·» в шапке — формат, оставить).
6. **Задание:** скопировать `team/out/2026-10-31/express_nhl_mk.py` в `team/out/D/express_mk.py`, поправить: D, файлы
   текстов, записку (ноги, кэфы, шансы, самая слабая нога, «да купон», «нравится формат?»). `make` — 
   `team/picks/express_render.py team/out/D/express_coupons.json out/express/D`; сообщения: на каждый купон `photo`
   (e<k>_feed.jpg + подпись), для купона 1 ещё `animation` (e1_anim.mp4 + та же подпись), `album` сторис, записка.
   `python3 team/out/D/express_mk.py` → `team/out/D/express.json`. Проверить: подписи ≤ 1024.
   Посмотреть 1–2 картинки локально: `python3 team/picks/express_render.py team/out/D/express_coupons.json out/express/D`
   и Read `out/express/D/e1_feed.jpg`.
7. **Отправка:** коммит (coupons, тексты, facts, mk, json) → push → `gh workflow run itogi.yml --ref <ветка> -f
   payload='{"kind":"team","job":"team/out/D/express.json"}'` → дождаться `completed success`. Неудача без логов:
   ошибки видны владельцу в боте («не всё отправилось»); для диагностики — временный скрипт отправки с пометками
   `::notice` по каждому сообщению (31.10: так нашли, что jpg не попали в git).
8. **Instagram** — только после «да купон» (ниже). Без этого ничего не публиковать.
9. **Записать:** строка в `team/NOW.md` «События» («ЧЧ:ММ · <аккаунт> · экспрессы D: купоны …, run …») и в `team/LOG.md`;
   push; руководителю — 3–5 строк (купоны, кэфы, шансы, run, что ждёт владельца).

1. Подпись для ленты — `ig-caption` + `ig-human`, голос `.claude/instagram/voice.md`, 3 хэштега, призыв в Telegram:

2. План `team/out/D/express_ig_plan.json` (образец — 31.10): `feed`, `story` (пути `out/express/D/e<k>_*.jpg`),

   `team/picks/express_ig.py` ничего не публикует.
3. Задание `team/out/D/express_ig.json`: `make` — сначала `team/picks/express_render.py …` (картинки), затем
   `team/picks/express_ig.py team/out/D/express_ig_plan.json`. Лента (картинка + подпись) и сторис (`media_type=STORIES`);
   картинку Instagram берёт по ссылке litterbox (1 ч); секреты IG_TOKEN / IG_USER_ID — в itogi.yml, не трогать.
   Ссылки скрипт присылает владельцу в бот и пишет пометкой `EXPRESS_IG`.
4. Строка в `team/NOW.md` и `team/LOG.md`.
