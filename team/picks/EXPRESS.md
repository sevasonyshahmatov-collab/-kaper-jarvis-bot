# Рубрика «Экспресс» (владелец 31.10; с 01.11 — ежедневно)

Задача владельца: купоны из самых вероятных событий дня «в виде поста, и почему каждое событие должно зайти». Главное —
**шанс зайти, а не кэф**. Формат одобрен владельцем 31.10 («пойдёт»). Купоны — черновиками владельцу в бот с кнопкой «Опубликовать»: нажал —
купон уходит в канал и в Instagram (лента + сторис). Без нажатия — никуда.

## Правила купона
1. **Нога** — исход с вероятностью модели **от 65 %** (первое число в строке «Что заходит» brief.md) и кэфом Pinnacle
   **1,20–1,65**; ноги отбираются по убыванию вероятности.
2. **Рынки и разнообразие (владелец 31.10): в купоне не больше одной форы.** Остальные ноги — индивидуальные тоталы
   команд (ИТБ/ИТМ), общий тотал, победа (в основное время / итоговая). 1Х/Х2 не берём. В НХЛ — «в основное время»,
   кроме пометки «с ОТ = осн. время на этой линии».
3. Из одного матча — одна нога; **матчи между купонами дня не повторяются**.
4. **Общий кэф** = произведение, до сотых: цель **1,80–2,00**, не жёстко — нет сочетания, тогда 1,75–2,05. Среди
   подходящих — наибольшее произведение вероятностей.
5. **Шанс купона = произведение вероятностей ног** — только в служебной строке `team/picks/EXPRESS_LOG.md` и
   руководителю (с 1/кэф и самой слабой ногой), **не владельцу в пост** (владелец 31.10).
6. Всё это делает `team/picks/express.py` (константы P_MIN, K_MIN/K_MAX, TARGET/WIDE, MAX_FORA вверху файла).

Калибровка: отдельной проверки заходимости инд. тоталов у нас нет (31.10); общая заходимость прогнозов НХЛ 15–29.10 —
53 % при обещанных 61 % (`README.md` §3). Купоны — проба, итоги считать: `team/picks/EXPRESS_RESULTS.md` (завести с
первыми итогами: дата, купон, ноги, зашло/нет). Расчёт по каждому купону — `EXPRESS_LOG.md`.

## Пост — формат по умолчанию (владелец 31.10: «просто сам экспресс и снизу общий кэф. И всё»)
- **Гифка** (MP4 H.264 без звука, ~4,6 с, по кругу): события выезжают по очереди, затем «Общий кэф». Telegram —
  `animation`; статичная картинка последнего кадра — запасной вариант (`express_post.py --static k`).
- На баннере и в подписи только: шапка (лига · даты · «экспресс»), события (матч, время МСК, ставка, кэф), «Общий кэф: X».
  **Без** шанса / процентов модели, без «почему зайдёт», без строки «экспресс не зайдёт, если…». Хэштеги остаются.
```
НХЛ · 31 октября – 1 ноября · экспресс

1. <b>Лос-Анджелес — Баффало</b>, 23:00 МСК
фора Лос-Анджелеса +2,5 · 1,22
2. <b>Монреаль — Питтсбург</b>, 1 ноября, 02:00 МСК
индивидуальный тотал Питтсбурга больше 1,5 в основное время · 1,22

Общий кэф: <b>1,83</b>

#нхл #экспресс #jarvibet
```
- **В шапке нет времени** — бот публикует купон по кнопке сразу (не за 1,5 / 4 ч до матча, как одиночные прогнозы).
  Номер купона — `ДДММ-eN` (3110-e1); номера ММДД-N одиночных прогнозов не трогать.
- Подписи собирает `team/picks/express_post.py` (из `express_coupons.json`); руками текст не пишем. Без БК, промокодов,
  «верняка», гарантий.
- Картинки: `render/express_card.py` → `team/picks/express_render.py`: на купон `e<k>_anim.mp4` (лента, гифка),
  `e<k>_feed.jpg` (запасная картинка и лента Instagram), `e<k>_story.mp4` (сторис-видео) и `e<k>_story.jpg` (запасная),
  1080×1350 и 1080×1920, ≤ 1,5 МБ. **Рисует Actions** (jpg/mp4 в `team/out` git не хранит), ffmpeg ставит сам.

## Итог экспресса (владелец 01.11)
Опубликованный купон бот запоминает (`EXW_<ДДММ-eN>`: номер поста в канале, ноги). Когда доиграна последняя нога, бот сам
запускает `express_result_auto` (`team/picks/express_result.py --auto`, payload `exres`) и присылает владельцу черновик
«Итог экспресса» (баннер с ✅/❌, номер `ДДММ-eNr<пост>`); один раз на купон. «Опубликовать» выпускает его в канал **ответом на пост
купона**; проигрыш — тоже итог (❌, спокойный тон). Учёт — `team/picks/EXPRESS_RESULTS.md` (строку дописывает бот при публикации).
Проверка без затрат: `node tools/gas_mock/team_express_result_test.js`.

## Ежедневный запуск (задача 08:23 МСК → новый чат; шаги для холодного чата)
`D` — сегодня по Москве (`TZ=Europe/Moscow date +%F`). Ветка команды `claude/project-migration-old-account-6e31vz`
(`git checkout` её и `git pull --rebase`). Инструменты: `gh` (запуск и пометки Actions), python3.
1. **Уже сделано?** Есть `team/out/D/express_msgs.json` и строка «экспресс» за D в `team/NOW.md` («События») — ничего
   не делать, одна строка руководителю. Оборванный запуск — продолжить с того, что есть в `team/out/D/`.
2. **Данные** (Actions, ~2 мин на лигу; README §1, «Логи Actions из облака закрыты»): по заданию на лигу —
   `team/out/D/express_khl_data.json`: `{"day": "D", "make": ["team/picks/notice_brief.py khl D"], "messages": []}`, так же
   `express_nhl_data.json` с `nhl` (в одном задании две лиги нельзя: у обеих пометки PB_1/N). Если утренние прогнозы уже
   собрали данные за D (`team/out/D/picks_khl_data.json` / `picks_nhl_data.json`, запуск success) — взять их run.
   Коммит, push, `gh workflow run itogi.yml --ref <ветка> -f payload='{"kind":"team","job":"team/out/D/express_khl_data.json"}'`;
   `gh run list -w itogi.yml -L 1` → номер; ждать `gh run view <N> --json status,conclusion`; job — `gh run view <N> --json jobs`.
   Сборка: `gh api repos/sevasonyshahmatov-collab/-kaper-jarvis-bot/check-runs/<job>/annotations --paginate -q
   '.[]|select(.title|startswith("PB_"))|(.title|split("_")[1]|split("/")[0])+" "+.message' | sort -n | cut -d' ' -f2- |
   tr -d '\n' | base64 -d | tar xz -C out/picks/<лига>-D` (папку создать заранее).
   НХЛ — игровой день D = матчи вечером D и ночью на D+1 по Москве.
   Футбол (если идёт проба `jarvis-picks-football`): строки FD* из запуска `foot_notice.py D` (пометки PB_ → `base64 -d |
   gunzip > out/picks/foot-D/fd.txt`). Нет данных какой-то лиги — без неё.
3. **Купоны:** `python3 team/picks/express.py --khl out/picks/khl-D/brief.md --nhl out/picks/nhl-D/brief.md
   [--foot out/picks/foot-D/fd.txt] --sizes 3,3,2 --out team/out/D/express_coupons.json` → 3 купона по 2–3 ноги.
   Нет купона — так и сказать, не натягивать. Матч начинается меньше чем через 2 ч после отправки — убрать его раздел
   из копии brief.md и пересчитать.
4. **Служебная строка** на каждый купон в конец `team/picks/EXPRESS_LOG.md`: дата, номер, ноги с кэфами и p, общий кэф,
   шанс модели против 1/кэф, самая слабая нога (сверить её LAST в brief.md: голы в основное время).
5. **Посты:** `python3 team/picks/express_post.py D` → `express_posts.json`, `express_msgs.json`, `express.json`
   (купоны гифкой с кнопками ДДММ-eN, затем альбом сторис). Прочитать подписи (печатает их): названия команд, падежи
   («фора Лос-Анджелеса»), «в основное время» у НХЛ. Картинки посмотреть локально: `python3 team/picks/express_render.py
   team/out/D/express_coupons.json out/express/D` → Read `out/express/D/e1_feed.jpg`.
6. **Отправка:** коммит (coupons, posts, msgs, express.json, EXPRESS_LOG.md) → push → `gh workflow run itogi.yml --ref
   <ветка> -f payload='{"kind":"team","job":"team/out/D/express.json"}'` → completed → итог по сообщениям:
   `gh api …/check-runs/<job>/annotations -q '.[]|.title+" "+.message' | grep EX` (EXRENDER — картинки одной строкой,
   EXSEND_<i> ok / ОШИБКА / НЕТ ФАЙЛОВ). Не ушло — дослать только эти номера: задание с тем же `make`-render и
   `team/picks/express_send.py team/out/D/express_msgs.json 1 3`. Проверка без отправки — `--dry`.
7. **Instagram** — сам: владелец жмёт «Опубликовать» → бот публикует в канал и запускает Instagram (ниже). Руками не
   публиковать.
8. **Записать:** строка в `team/NOW.md` «События» («ЧЧ:ММ · <аккаунт> · экспрессы D: купоны …, run …») и в `team/LOG.md`;
   push; руководителю — 3–5 строк (купоны, кэфы, шанс модели, самая слабая нога, run).
