# Личный кабинет: план этапа C (вход через Telegram)

Статус на 05.11: этап B готов (`team/site/v3a/me/index.html`, `assets/fav.js`, `assets/me.js`) — без сервера, избранное только в `localStorage` браузера. Кнопка «Войти через Telegram» пока просто ведёт в бота (`https://t.me/jarvibet?start=site_account`). Этап C не включён.

## Что нужно для настоящего входа
- **Домен.** Telegram Login Widget работает только на домене, привязанном к боту: в BotFather команда `/setdomain`. На адресе GitHub Pages и на `localhost` виджет не заработает.
- **Проверка подписи на сервере.** Telegram отдаёт сайту поля (id, имя, фото, `auth_date`, `hash`). Сайт обязан проверить `hash` на сервере: ключ = SHA256(токен бота), подпись = HMAC-SHA256 от строки «поле=значение» (поля по алфавиту, через перевод строки), сравнить с `hash`; проверить, что `auth_date` свежий (не старше суток). Проверять подпись в браузере нельзя: токен пришлось бы отдать посетителям.

## Варианты сервера
1. **Cloudflare Worker.** Бесплатно, мало кода (проверка подписи + выдача подписанной cookie). Минус: серверы вне РФ (см. 152-ФЗ ниже).
2. **Apps Script бота.** Уже есть, токен уже там. Минус: Google, вне РФ; медленный; лимиты запросов; смешиваем сайт с кодом бота (правки бота идут отдельно через PR).
3. **Вход по одноразовому коду через бота.** Сайт показывает код, человек отправляет его боту (`/start site_<код>`), бот подтверждает. Домен для виджета не нужен, но нужен небольшой сервер хранения кодов и отметка «код подтверждён» (Worker + KV или таблица бота).

## Что хранить (рекомендация)
Минимум: `telegram_id`, имя, список клубов.
**Вариант без базы:** после проверки подписи выдать подписанную cookie (id + срок), а избранное по-прежнему держать в браузере и при входе сливать с локальным. Тогда на сервере не лежит ничего, кроме секрета подписи. Минус: на другом устройстве список не появится сам, пока нет хранилища. Если нужен общий список на всех устройствах — понадобится хранилище `telegram_id → [клубы]` (одна маленькая таблица).

## 152-ФЗ
- Telegram id и имя — персональные данные. Нужны: политика обработки, согласие (галочка рядом с кнопкой входа), указание цели и срока хранения, способ удалить данные.
- Если данные хранятся на сервере: базы граждан РФ должны быть в РФ. Cloudflare и Google — вне РФ, значит хранить там id и имя нельзя; нужен российский хостинг/облако (или схема «cookie без базы»: на сервере вне РФ данные не сохраняются, но это стоит проверить с юристом: проверка подписи уже обрабатывает id и имя).
- Уведомление Роскомнадзора об обработке персональных данных (до начала обработки, если нет исключений).
- Отдельно: Google Fonts и jsdelivr уже уводят IP за границу (`SECURITY_0411.md`, п. 4, 10).

## Что нужно от владельца
1. Домен (и куда он смотрит: Cloudflare, российский хостинг).
2. Выбрать вариант: виджет + Worker, одноразовый код через бота или оставить без входа (только браузерное избранное).
3. Нужно ли общее избранное на всех устройствах (тогда база в РФ) или хватает «этот браузер».
4. Решение по 152-ФЗ: кто оператор данных (ИП/самозанятый/ООО), текст политики и согласия, уведомление РКН. Лучше показать юристу.
5. Подтвердить, что бот умеет обрабатывать `/start site_account` (сейчас он просто показывает приветствие; метка нужна только для статистики переходов), и что бот будет присылать — подпись на кнопке описывает только то, что есть сейчас (личные итоги после игрового дня и карточки команд).
6. Токен бота в этот план и в репозиторий не записывать: он нужен только серверу (секрет Worker/Actions).

## Порядок работ после решений
1. Домен и `/setdomain` → 2. Worker с проверкой подписи и cookie → 3. кнопка входа в `me/index.html` вместо ссылки на бота → 4. слияние избранного (локальное + серверное) → 5. политика, согласие, удаление данных («Очистить мои данные» + кнопка удаления на сервере).
