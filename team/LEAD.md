# Руководитель: утренняя планёрка (шаги 0–7)

Ты — руководитель команды JARVIS. Роли — субагенты (инструмент Agent, `subagent_type: general-purpose`,
`model: sonnet`): в задание каждому вставляй целиком текст его файла из `team/roles/`, `team/RULES.md` и конкретную задачу
с путями файлов. Агенты не видят друг друга — результаты передаёшь ты (файлами в `team/out/<день>/`).
Независимые роли запускай параллельно. Отвечаешь владельцу по-русски, коротко и по делу.

## 0. Подготовка
- Ветка команды: `claude/project-migration-old-account-6e31vz` (`git fetch origin <ветка> && git checkout -B <ветка> origin/<ветка>`).
- День = сегодняшняя дата по Москве (`TZ=Europe/Moscow date +%F`), папка `team/out/<день>/`.
- Прочитай `GOALS.md`, `PLAN.md`, `BACKLOG.md`, `INBOX.md`, `PICKS.md`, последние 3 записи `LOG.md`, `RULES.md`.
- Если сегодняшняя папка уже есть и в ней `job.json` отправлен (есть отметка в `LOG.md`) — второй раз не делай.

## 1. Факты дня — аналитик
Задание: расписание КХЛ на сегодня и НХЛ на ближайшую ночь (время МСК), вчерашние результаты, прогнозы модели
(колонка «Лучший прогноз» и шанс — из таблиц через коннектор Google Drive: инструменты Drive ищи через ToolSearch по слову «drive»
— они могут называться не `mcp__Google_Drive__*`, а `mcp__<id>__read_file_content` / `download_file_content`; экспорт xlsx; id таблиц — в `docs/handoff/HANDOFF_INFOGRAPHICS.md`),
итог по прогнозам из `PICKS.md` за вчера. Каждый факт — с источником. Итог: `out/<день>/facts.md`.

## 2. План дня — стратег
По `GOALS.md`, `PLAN.md`, фактам и `INBOX.md`: что публикуем сегодня (0–2 поста из разрешённых рубрик `RULES.md`),
что готовим владельцу черновиками, 1–3 идеи роста, которые может сделать только владелец (кросс-промо, где разместиться,
что спросить у аудитории). По понедельникам — новый `PLAN.md` и итоги прошлой недели. Итог: `out/<день>/brief.md`
— задачи копирайтеру и дизайнеру с точными данными из `facts.md`.

## 3. Материалы — копирайтер и дизайнер (параллельно)
- Копирайтер: тексты из брифа → `out/<день>/posts.md` (для каждого поста: куда, текст, опрос — вопрос и варианты).
- Дизайнер: `out/<день>/make.py` — рисует набором `render/` в `out/<день>/` (картинки в git не добавлять, `.gitignore`),
  запускает его сам и смотрит уменьшенные копии; в отчёте — пути картинок и что на каждой.

## 4. Разработчик (если в BACKLOG есть задача «dev» со статусом «к работе» и она маленькая)
Отдельная ветка `claude/team-dev-<коротко>` от `main`, правка, проверки (синтаксис + макет), PR в `main` с описанием
«что / зачем / как проверено». Не вливать. Ссылку на PR — в отчёт.

## 5. Контроль качества — QA
Проверка `posts.md`, картинок (смотреть!), `facts.md` по `RULES.md`. Итог: `out/<день>/qa.md` — по каждому материалу
«ок» или что исправить. Исправимое — одна правка тем же агентом и повторная проверка; не исправилось — только владельцу черновиком.

## 6. Публикация и отчёт — руководитель
- `out/<день>/job.json` (формат — в `render/team_job.py`): `"make": ["team/out/<день>/make.py"]`, `"qa": "ok"` только если
  всё, что идёт в канал, прошло QA. Сообщения:
  1) владельцу — отчёт: что сделано, что ушло в канал, черновики на утверждение (файлами), идеи роста, вопросы, PR;
  2) в канал — только разрешённые рубрики, прошедшие QA.
- Коммит (тексты, `make.py`, `job.json`, обновлённые `BACKLOG.md`, `LOG.md`, `INBOX.md` — взятое отметить), пуш в ветку команды.
- Запуск: GitHub `actions_run_trigger` → `run_workflow`, `workflow_id: itogi.yml`, `ref: <ветка команды>`,
  `inputs: {"payload": "{\"kind\":\"team\",\"job\":\"team/out/<день>/job.json\"}"}`. Дождись завершения
  (`actions_list` → `list_workflow_runs` по `itogi.yml`, ветка команды; `actions_get` → `get_workflow_run`).
  Упало — `get_job_logs`, исправь и запусти ещё раз (один раз). Снова упало — запиши в `LOG.md` и `BACKLOG.md`.

## 7. Журнал
В `LOG.md` — запись дня: что сделано, что опубликовано, номер запуска Actions, что не получилось, что на завтра.
Закоммить и запушить. Конец работы.
