# Конвейер шортсов КХЛ и НХЛ

Задание: `docs/handoff/CONVEYOR.md`. Шаблоны: `team/reels_selected/README.md`. Claude в ежедневной работе не участвует:
всё считается и собирается в GitHub Actions (`.github/workflows/reels-daily.yml`).

## Что делает один запуск
**Один матч — один ролик** (владелец 17.10): шаблоны идут по очереди, прошли все — круг начинается заново. Один и тот же
прогноз на разных шаблонах не делаем.

1. **plan** — матчи дня и сыгранные матчи: КХЛ — приложение КХЛ (`team/picks/khl_data.py`, там же линия Фонбета), НХЛ —
   API НХЛ (`team/picks/nhl_data.py`, игровой день = дата по Нью-Йорку, у нас ночь на следующее число); линия Pinnacle
   (`team/picks/pin.py`), «Что заходит» по каждой паре (`team/picks/calc.py`).
   Прогноз (`pick.py`) — правило владельца 17.10: самое вероятное событие (от 45 %) с кэфом **1,6–2,3**; среди ставок в
   пределах 4 п. п. от лучшей — кэф под матч: равный (П-меньший/П-больший ≥ 0,75) — 1,6–1,7, аутсайдер против сильного
   (< 0,5) — 1,8–2,0. В один день — по возможности разные виды ставок. Нет такой ставки или линии — матча в роликах нет.
   НХЛ: к форе и тоталам дописывается «в основное время». Ролик — на каждый матч с прогнозом (`max` > 0 — только самые
   уверенные). Владельцу — список матчей дня с прогнозами.
2. **render** (по 3 ролика на задание, задания идут параллельно) — **все утверждённые шаблоны строго по очереди**, независимо
   от вида ставки (владелец 19.10), начало круга сдвигается по дням. 20 вариантов: 9 шаблонов 14.10, 5 вариантов 14.10 с
   треками 16–17.10 («Кино» + vampire, «Граффити» + demons, «Приборка» + doomsday, «Скачки» + cant_say, «VHS» + two_faced),
   12.10 — «Сравнение», «Терминал», «Карточка», «Состав» (slx, kizaru, vace). Не в очереди: «Купон» и «Топ-3» (11.10) —
   на несколько матчей сразу, «Чат» — нет трека refl. Две версии: со звуком и `_clean`. Форма клубов — `form.py`.
   Если заданы секреты `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN` — ролик (со звуком) сразу загружается на
   канал (`youtube.py`) с доступом «для всех» (владелец 17.10), ссылка — в начале подписи в Telegram. Пока Google не одобрил
   приложение: YouTube может оставить ролик закрытым (в подписи будет сказано), ~6 загрузок в день (кончились — «загрузите вручную»), токен живёт 7 дней (режим Testing;
   обновить `YT_REFRESH_TOKEN` через OAuth Playground).
3. Ролики — артефакт запуска на **2 дня**, потом GitHub удаляет их сам. В репозиторий не кладём.

## Короткие ролики (владелец 30.10)
Каждый ролик ужимается до ~13 с (`core.Short`): из шаблона берутся сцены `scenes()` (команда 1, команда 2, прогноз от дропа),
склейки — на долю трека, анимации быстрее не больше ×1,6, длинная сцена команды обрезается спереди. Трек ставится так, чтобы
прогноз встал ровно на дроп. В конце — карточка-призыв (`make.card(i)`: «protocol» / «share» по `(i // 2) % 2`, заставка А/Б
по `i % 2` — сравниваются отдельно); её текст — первой строкой подписи Instagram, строка «Прогноз на матч …» — второй
(повторы ищутся по ней: `instagram.key_line`). Снимок Instagram помечает ролики `fmt` (short/long), `card`, `ab`.
Выключить — переменная `REELS_SHORT=0`. В логе: `REEL … | short protocol | …`.

## YouTube: приоритет и пакет владельцу (владелец 22.10)
Квоты хватает на ~6 загрузок в сутки, а НХЛ (02:00) и КХЛ (02:30 МСК) попадают в одни сутки квоты. Поэтому `plan`
отмечает `yt` у самых ценных роликов (`yt_priority`: прайм-тайм, топ-клубы, уверенность; КХЛ — 4, НХЛ — 2, переменные
`YT_SLOTS_KHL` / `YT_SLOTS_NHL`) — только они грузятся на YouTube сами. Каждый ролик кладёт рядом `<ролик>.json`, и после
всех частей задание `pack` (`pack.py`) шлёт владельцу всё разом: альбомы роликов для ручной загрузки, один текст с
названиями и описаниями для Studio и ссылку на архив запуска (версии без музыки, обложки). Прежняя отправка каждого
ролика отдельно — `REELS_TG_EACH=1`.

## Запуск
- По расписанию (владелец 30.10: «ролики на день вперёд», работает из `main`):
  - **КХЛ — 16:00 МСК, матчи ЗАВТРА.** Линия на завтра (Фонбет из приложения КХЛ + Pinnacle) днём уже стоит: проба 30.10 в
    13:00 МСК — матч 31.10 15:00 с линией за 26 ч. Нет игр завтра — берётся следующий день, не дальше двух суток от запуска
    (`make.py plan … --spare 1`; настоящий день уходит в артефакты и подписи).
  - **НХЛ — 02:00 МСК, игровой день НХЛ = дата по Москве** (матчи ночи на следующее число). Раньше нельзя: проба 30.10
    13:00 МСК — на игровой день 31.10 (10 матчей) линии нет ни у Pinnacle, ни у ESPN; у Pinnacle она появляется примерно
    за сутки до первого матча (около 02:00 МСК). То есть НХЛ выходит за 17–19 ч до матча — это предел, который даёт рынок.
    Нужно раньше — проверять `dry` (ниже) по вечерам и сдвигать `cron` НХЛ.
  - **Выкладка** (`make.publish_time`): окно 09:00–22:00 МСК, шаг 90 мин. Ролик на завтра выходит в Instagram/YouTube **сразу
    после сборки** (КХЛ — с ~16:20 накануне), всё, что не влезло в окно, — на следующее утро с 09:00, но не позже чем за 2 ч до
    матча. Ночью не выкладываем.
  - **Подписи:** первая строка — «Прогноз на матч … КХЛ, суббота, 31 октября, 15:00 МСК» (по ней ищут повторы, «завтра» в
    неё не входит), вторая — «Матч: завтра, суббота, 31 октября, 15:00 МСК» (ночной НХЛ — «завтра ночью — в ночь на
    воскресенье, 1 ноября»). В ролике дата и день недели уже стоят на заставке.
  - **Без дублей:** `instagram.posted` (уже выложено) и очередь `ig_queue` (одна запись на первую строку подписи). Ручной
    повторный запуск того же дня после выкладки — безопасен; до выкладки YouTube-автозагрузка могла бы задвоиться, не гонять зря.
  - **Лимиты:** YouTube ~6 в день — КХЛ 4 + НХЛ 2 слота (`YT_SLOTS_*`), остальное пакетом владельцу; Instagram 50 через API —
    КХЛ 3–6 + НХЛ 8–15 в день, хватает с запасом.
  - **Известный риск:** ролик собран за сутки и по линии на момент сборки; к матчу линия может уйти. Ничего не перевыкладываем
    (дубли хуже). Решение одной строкой для владельца: если ушла сильно — удалить ролик вручную; автоматически не трогаем.
- Вручную: Actions → «Шортсы — конвейер» → Run workflow (лига, день, сколько роликов); из бота/таблицы —
  `repository_dispatch` типа `reels` с `{"league": "nhl", "day": "ГГГГ-ММ-ДД"}`; из ветки `claude/**` — записать в
  `team/reels_daily/RUN` строку «лига день» (`nhl 2026-10-17`) и запушить.
- Только расчёт без сборки и без Telegram («есть ли линия на завтра»): Run workflow с `dry` = 1 — в логе строки `DRY …`.
- Проверка кадрами без треков и Telegram: `python team/reels_daily/make.py plan khl <день>` (нужен доступ к API КХЛ), затем
  `PYTHONPATH=render python team/reels_daily/make.py render khl <день> --part 1 --frames 2,9,15,20` → `out/reels_daily/khl-<день>/`.

## Instagram — очередь (владелец 26.10)
Ролики в Instagram выходят не пачкой ночью, а по одному днём — по расписанию YouTube (`make.publish_time`: с 09:00 МСК
шагом 90 мин, КХЛ +45 мин, не позже чем за 2 ч до матча). Ночью `make.py` загружает ролик в контейнер и пишет задание
`<ролик>.igq` в артефакт; выкладывает `ig_queue.py` из `.github/workflows/ig-queue.yml` (с каждым тиком соцсетей,
пауза между роликами 25 мин, за 30 мин до матча — уже не выкладывает). В логе — строки `INSTAGRAM в очереди на …`
и `IGQ …`. Выключить: переменная репозитория `IG_QUEUE=0` — ролики снова сразу.
