# jarvis-brief — из идеи подробное ТЗ

Вход: идея владельца как есть (его словами). Выход: одно ТЗ в формате ниже, без выполнения самой работы.

1. Пойми, о чём идея, и найди в репозитории, что уже есть по теме (не больше 5–8 файлов): `CLAUDE.md`, `team/RULES.md`,
   `team/BACKLOG.md`, `team/LOG.md`, нужный раздел (`team/…`, `render/…`, `docs/handoff/…`), голос —
   `.claude/instagram/voice.md`. Похожая работа уже была — опирайся на неё и назови файлы.
2. Додумай то, что владелец не сказал, но подразумевает: площадка (Telegram-канал / бот / Instagram / YouTube / сайт),
   формат и размеры, стиль (как в последних работах: тёмный фон, золото, эмблемы без обводки, объём и свечение,
   «показать, а не рассказать»), объём, срок. Где додумал — пометь «(допущение)».
3. Напиши ТЗ:

```
## Задача: <одной строкой>
**Зачем:** <какую цель владельца решает — рост канала, доверие, экономия его времени…>
**Для кого:** <подписчики канала / Instagram / сам владелец>
**Что сделать:** <пошагово, 4–10 пунктов, конкретно: что, где лежит, каким скриптом или скиллом>
**Данные:** <откуда цифры — только настоящие: stats/months.json сайта, team/PICKS.md, выгрузка таблицы, API лиг>
**Как должно выглядеть:** <формат, размеры, стиль, примеры похожих файлов>
**Правила:** прогнозы и кэфы — только черновиком владельцу; без БК, промокодов, гарантий, выдуманных цифр;
  в main — только через PR; <что ещё из team/RULES.md относится к задаче>
**Готово, когда:** <проверяемые признаки: файл есть, владелец получил в бот, пост вышел, ссылка>
**Спросить у владельца:** <только то, без чего нельзя начать; можно начать — «нет»>
**Скиллы и инструменты:** <jarvis-*, ig-*, плагины из CLAUDE.md «Продвижение»>
```

4. Верни только ТЗ. Идея противоречит правилам канала (выдуманные цифры, кэфы в канал) — так и напиши
   в «Спросить у владельца» и предложи честный вариант.
