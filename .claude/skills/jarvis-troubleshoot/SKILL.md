# jarvis-troubleshoot

Логи целиком не читать: последний запуск нужного workflow → `get_job_logs` с небольшим `tail_lines` (или
`gh run view <id> --log-failed | tail -40`) и метки PICK, POSTMATCH, DAILY, DAILY_SCORES, SITE, `→ owner`.
Сеть облачной сессии закрыта для khl.ru, api-web.nhle.com и Telegram — проверять только через Actions.

## 1. Сначала — общие причины (почти всегда одна из них)
| Признак | Причина | Что делать |
|---|---|---|
| Все задания падают за 3–4 с, без шагов | Кончились минуты Actions (было 23.10, пока репозиторий был приватным) | Проверить, что репозиторий публичный; отчёт `actions-minutes.yml`. Владельцу — коротко. После возврата перезапустить упавшие |
| Запуска в нужное время нет или он на 10–60 мин позже | GitHub опаздывает с расписанием (особенно `site.yml`, 03:23 / 10:23) | Подождать до часа; критичное — запустить вручную |
| Шаг «Нарисовать и отправить» висит > 5 мин (обычно ~1,5) | Зависла хроника приложения КХЛ или служба текста (23.10, Динамо — Локомотив, причина не разобрана) | Отменить запуск и перезапустить один раз, не ждать 20 мин; снова висит — пост вручную (`team/out/2026-10-23/pm_lok_din.*`) и запись в LOG.md |
| `git push` / fetch → 403, «Resource not accessible by integration» | Слетел доступ GitHub (26.10) | Владельцу: переподключить GitHub на https://claude.ai/connect-github и проверить, что приложение Claude стоит на репозитории с правом записи |
| Инструменты `mcp__github__*` → «invalid session» | Сессия MCP GitHub протухла, git при этом работает | Читать запуски через `gh run list` / `gh run view`; PR вливать git'ом. Запуск workflow через `gh workflow run` в облаке не проверен — пробовать один раз |
| Push отклонён с HTTP 413 | Пуш из устаревшей неглубокой копии | `git fetch origin <ветка>`, rebase, пуш снова |
| Удаление ветки отклонено | Прокси сессии не даёт удалять ветки | Попросить владельца удалить в GitHub |
| Логи Actions не скачиваются: Forbidden с `blob.core.windows.net` | Хранилище логов закрыто сетью облачной сессии (26.10) | Скрипт печатает нужное пометками `::notice title=МЕТКА::…`, читать `gh api repos/<repo>/check-runs/<job_id>/annotations` (пример — `team/social/ig_snapshot.py`). Запуск `gh workflow run` из облака работает |
| Instagram: «(#10) Application does not have permission for this action» на `/insights` | У ключа `IG_TOKEN` нет права на статистику (26.10) | Владельцу: выпустить ключ с правом `instagram_manage_insights` и заменить секрет `IG_TOKEN` |

## 2. По видам работы
**Итоги дня (08:30, `team/daily/morning.py`)**
- С 27.10 бот сначала присылает «Сверку перед итогами»; без «✅ Всё верно» итоги не собираются (одно напоминание до 12:00).
  «Итоги не пришли» — сначала спросить или посмотреть в `team/INBOX.md`, нажата ли сверка.
- Матча нет в итогах — он не был доигран к сборке (25.10 Нэшвилл): перезапустить после финала через `jarvis-recap`.
  Окно матчей — с 08:00 вчера до 08:00 сегодня МСК.
- Не та ставка — итоги взяли черновик, а не правку владельца (23.10 Чикаго — Монреаль, 25.10 Спартак, СКА — ЦСКА).
  Правки — строки «правка владельца в боте» в INBOX; пересобрать через `jarvis-recap`. Правку прямо в канале и посты,
  опубликованные вручную, бот не видит — для них кнопка «Поправить».
- В логе `DAILY {… "picks": N …}`: N должно совпасть со списком ставок.

**Послематчевый пост (`team/postmatch/run.py`, записи `PMW_<pid>`)**
- Бот помнит только прогнозы, опубликованные кнопкой «Опубликовать»; опубликованные вручную — `jarvis-postmatch`.
- «Пост прогноза в канале не найден» — итог выйдет обычным постом, не ответом.
- День в задании — дата начала матча по МСК (НХЛ ночью — уже следующее число).
- Текст звучит как ставка на команду, когда ставка на тотал (17.10) — исправлено в `run.py`; повторилось — смотреть там
  разбор вида ставки.

**Отправка владельцу (`itogi.yml`, `jarvis-send`)**
- `MEDIA_CAPTION_TOO_LONG` — подпись к фото или гифке длиннее 1024 знаков (26.10, Трактор — Сибирь). Сократить или
  прислать картинку и текст отдельными сообщениями (текст — до 4096).
- «Request Entity Too Large» — несколько видео одним пакетом > 50 МБ (12.10, run 81). Каждое видео — отдельным сообщением.
- `PAYLOAD=null` в скрипте задания — payload не дошёл до шага; ключи и секреты в payload не передавать никогда (виден
  в Actions) — только секреты репозитория (`TRACKS_KEY`).

**Прогнозы (`jarvis-picks`, `team/picks/README.md`)**
- Матч без поста — нет линии Pinnacle (обычное дело для 1–2 матчей НХЛ); в обзоре это сказано.
- Утренний запуск пропущен — недельный лимит запросов Claude или запланированная задача пришла поздно (13–15.10).
- `check.py` не пропускает пост — старый хэштег (теперь `#кхл #прогноз #jarvibet`) или фото вместо анимации.

**Ролики (`reels-daily.yml` в main, 02:00 НХЛ / 02:30 КХЛ)**
- Не вышли на YouTube — лимит YouTube ~6 загрузок в сутки и правило не больше 4 автозагрузок КХЛ в день. Загрузить
  вручную или ждать следующего дня.
- Нет звука трека — секрет `TRACKS_KEY` или ветка `claude/team-dev-tracks-v2`.

**Сайт (`site.yml` → репозиторий `sevasonyshahmatov-collab.github.io`)**
- Главная показывает пример «СКА — ЦСКА…» — исправлено 26.10 в `team/site/build.py` (`landing()`); вернулось — смотреть,
  что `window.__TODAY` не `null`.

**Зеркало и истории Instagram** — `ig-mirror.yml` раз в 2 ч (08:27–00:27), истории и карусель — `social-tick.yml` от
внешнего будильника cron-job.org: нет тиков — будильник, а не код.

## 3. Итог в основной чат
Одна-три строки: что сломалось, причина (строка таблицы или «новое»), что сделано (номер запуска), что нужно от
владельца. Новая причина — дописать строку в эту памятку и коротко в `team/LOG.md`.
Самому можно только то, что уходит владельцу (перезапуск итогов, поста, отправки). Всё, что меняет код, бота
(`apps-script/`), канал или настройки, — только предложить.
