## 1. Что это за проект

Телеграм-канал **«JARVIS | KXL»**, хендл **@jarvibet** — прогнозы на хоккей (КХЛ, плюс
иногда НХЛ). К каждому матчу и к каждому прогнозу делается баннер-инфографика
размером **1280×640**, плюс текст поста от лица автора канала.

Основа — питоновский набор `poster.py` (прислан автором в архиве вместе с README,
эмблемами и шрифтами). Всё остальное дописано поверх него, не меняя оригинал.

### Что именно делаем (виды баннеров)

| Тип | Назначение |
|---|---|
| **Предматчевая карточка** | один матч: эмблемы, «очки · игры», форма за 5 матчей с метками ОТ, время, линия П1/Х/П2 |
| **Афиша дня / «Матчи дня»** | все матчи дня на одном баннере: время + коэффициенты, фаворит золотом |
| **Постер прогноза** | наша ставка + кэф. Одиночник, двойник или мультикупон с общим кэфом |
| **Постер результата** | счёт матча + вердикт «ЗАШЁЛ» / «не зашёл» |
| **«ПРОГНОЗЫ ЗАШЛИ»** | несколько сыгравших ставок на одном баннере + экспресс-кэф |
| **«Итоги дня»** | все результаты дня на одном баннере |

## 2. Железные правила (согласованы с автором)

### Формат доставки
- Файлы всегда **вложениями для скачивания**, не встроенным предпросмотром — их нужно
  скачивать и сохранять.
- Формат по умолчанию — **JPEG** (`quality=95, subsampling=0, optimize=True`).
  PNG — только если попросил отдельно.
- ⚠️ Превью в чате раздаются как **webp**. Если сохранять картинку правым кликом из
  предпросмотра — получится .webp, хотя сам файл настоящий JPEG. Это не баг рендера.

### Язык дизайна: КХЛ vs НХЛ
Решение автора от 26.09, действует:
- **«Карточки»** (стеклянные карточки команд, золотой акцент `#FFC23D`) = **шаблон КХЛ**
- **«Бока»** (информация по бокам от эмблем) = **шаблон НХЛ**

### Тексты постов
- Пишутся **от лица автора канала**, без приписки «Джарвис».
- Про аналитическую таблицу **в публичных постах не упоминать** — аудитория о ней не знает.

### Тестовые прогоны
- Все проверки и повторные запуски — у себя, не в его таблицах. Не тратить его лимиты
  API (Gemini и др.).

## 3. Данные: правила достоверности

### Система начисления очков КХЛ 2026/27 — двухочковая
Любая победа = **2 очка**, поражение в ОТ/буллитах = **1**, поражение в основное = **0**.

**Главная проверка любой строки формы:**
```
points == 2 * wins + 1 * OT_losses
```
Ни один набор «очки / игры / форма» не идёт в рендер, не пройдя эту сверку.
(В начале проекта была ошибочно принята система 3-2-1-0 — переделывали.)

### Буквы формы (последние 5 матчей, слева старые → справа свежие)
- `W` — победа в основное время (зелёный круг «В»)
- `L` — поражение в основное время (красный круг «П»)
- `X` — победа в ОТ/буллитах (половина белая, «ОТ»)
- `O` — поражение в ОТ/буллитах (половина белая, «ОТ»)

### Прочие проверки
- Матч в ОТ/буллитах **всегда заканчивается разницей в 1 гол** — помогает отсеивать
  ложных кандидатов на ОТ.
- Коэффициенты проверяются на маржу: `Σ(1/кэф) ≈ 1.01–1.06`. Если больше — источник
  битый (был случай с линией на 40% маржи), выбрасываем.
- Время НХЛ приводим к МСК: американские матчи сдвигаются на сутки
  (напр. 23.09 в Далласе = 24.09 МСК).
- Экспресс = произведение кэфов, печатаем с 2 знаками.
- Целый тотал (напр. «Тотал больше 3») на точном числе — возврат. Фора (0) на ничьей — возврат.

### Источники
Работают: **WebSearch / WebFetch** — legalbet, livesport, kushvsporte, сайты клубов, khl.ru.
Не работают (блок egress-прокси): **Pinnacle API, GitHub, обычный curl/wget**.
Логотипы НХЛ автор присылает сам (лежат в `emblems/`: `minnesota.png`, `dallas.png`).

⚠️ Сводки WebFetch бывают ненадёжны (дубли, дефолтное «в основное время»).
Каждый набор данных перекрёстно проверяем по двум правилам выше, прежде чем рендерить.

## 5. Технические нюансы рендера

- Суперсэмплинг `S=2`: рисуем в двойном размере, потом `LANCZOS` вниз.
- Фон `_fluid_bg` — перелив двух клубных цветов; `_canvas_texture` — зерно.
- Тёмные логотипы получают подложку-«плашку» (`_needs_plate`, яркость < 95).
- Длинные названия клубов режутся — использовать `_fit`, а не фиксированный размер шрифта
  (была ошибка: «НЕФТЕХИМ», «ЛОКОМОТИ» в `render_results_day`; патч применён).
- В `nhl_variants._save` фон приводится к размеру оверлея:
  `if bg.size != (W, H): bg = bg.resize((W, H), Image.LANCZOS)`.
- `render_hits`: кэф может быть `None` → печатаем `'—'`, не падаем.

### Правило столкновения цветов — ВАЖНО
Если у двух команд одного баннера близкие клубные цвета, фон превращается в однотон.
Решение: на время рендера переопределяем `poster.BANNER[...]` на вторичный цвет клуба
из его же эмблемы.

Уже встречавшиеся пары и фиксы:
| Пара | Проблема | Фикс |
|---|---|---|
| Шанхай — Металлург | обе оранжевые | `BANNER['Металлург'] = (30, 48, 92)` — синий из логотипа |
| Северсталь — Сочи | обе жёлтые | вторичный цвет Сочи |
| Спартак — Автомобилист | обе красные | вторичный |
| Ак Барс — Спартак | зелёный vs красный (на «зашли») | вторичный |

Отдельно: `BANNER['СКА']` — **синий по замыслу автора набора**, не красный. Когда автор
спросил «почему на афише нет красного», ответ именно такой; были предложены два
красных варианта афиши на выбор.

## 6. Ежедневный рабочий цикл

1. Забрать расписание дня (время МСК).
2. Забрать результаты предыдущих матчей **с метками ОТ/буллитов**.
3. Забрать таблицу (очки, игры).
4. Восстановить список матчей каждой команды за последние 5 игр.
5. **Сверить `points == 2*wins + OT_losses`** для всех команд.
6. Забрать коэффициенты, проверить маржу.
7. Проверить пары на столкновение цветов, при необходимости переопределить `BANNER`.
8. Отрендерить, сконвертировать в JPEG, отдать вложениями.
9. Текст поста — от лица автора, без упоминания таблицы.

## 7. Что делаем и чего не делаем

**Делаем**
- Баннеры всех семи типов выше, по запросу на день или на отдельный матч.
- Тексты постов и превью для канала.
- Сбор коэффициентов и формы из открытых источников с проверкой.
- Правки по цветам, счёту, кэфу, тексту прогноза — по одному сообщению автора.

**Не делаем**
- Не правим `poster.py` — всё новое пишем в `recap.py` и отдельные модули.
- Не лезем в его Google-таблицы и не расходуем его API-лимиты.
- Не упоминаем таблицу в публичных постах и не подписываемся «Джарвис».
- Не отдаём файлы предпросмотром или текстовым документом.
- Не берём цифры из одного источника без сверки по двухочковой формуле и марже.
- Не публикуем данные, которые не удалось подтвердить — лучше сказать прямо.

- **`README_NHL.md`** — что какая функция ждёт на вход.

### Данные
Система очков НХЛ = нынешняя КХЛ: победа 2, поражение в ОТ/буллитах 1, в основное 0.
Работает та же проверка `points == 2*wins + OT_losses` и те же буквы формы `W/L/X/O`.
Время приводим к МСК — американские матчи сдвигаются на сутки.

### Эмблемы
**Все 32 клуба с настоящими логотипами** — автор прислал их 30.09.
Лежат как `emblems/nhl_<abbr>.png`, Миннесота и Даллас — `minnesota.png` / `dallas.png`.
Скачать логотипы нельзя: прокси режет Wikipedia и GitHub, проверено.
Новые логотипы ставить через `nhl.install_logo(name, path)`.

Колорадо стоит в «объёмной» версии с лёгкой тенью — остальные 31 плоские векторные.
Если найдётся плоский вариант, стоит заменить.
