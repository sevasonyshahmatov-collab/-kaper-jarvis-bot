# JARVIS: передача по визуальной части сайта (для Codex)

Подготовлено 19.11.2026. Владелец сайта просит посмотреть, как сайт выглядит, и предложить альтернативу.
Предложение сравним с текущим видом и выберем одно общее решение. Отвечай по-русски и простыми словами:
владелец не программист.

## Что можно и чего нельзя
- Сейчас нужен только разбор и предложение. В сайт и его репозиторий ничего не пушить, сайт не менять.
- Макеты и примеры — отдельными файлами (HTML/CSS или картинки), которые можно открыть локально.
- Только обычный просмотр страниц: без нагрузки, массовых запросов и действий против чужих сервисов
  (GitHub, API лиг, Telegram, хостинги картинок).

## Как устроено оформление сейчас
- **Темы.** На `<html>` атрибут `data-theme`. По умолчанию `arena` («Трансляция с арены»: тёмно-синяя ночная арена,
  лучи прожекторов). Есть `a`, `b`, `c` (`?theme=a|b|c`). Отдельно атрибут `data-bg`: фон по умолчанию `n`, `?bg=0` — прежний.
- **Лёгкий режим для слабых ПК.** Класс `html.lite` (`?lite=1`, `assets/nav.js`): неподвижный фон, без размытий.
  Это сделано только что, ломать нельзя. В любом предложении должен быть лёгкий вариант без `backdrop-filter`,
  без постоянных анимаций и тяжёлых теней.
- **Шрифты** (свои файлы, `assets/v3a.css`): `JV Display` (заголовки, цифры), `JV Wide` (расширенный, акценты), `JV Text` (текст).
- **Цвета — CSS-переменные** в `assets/v3a.css`. Основные для темы `a`: фон `--paper:#0a1220`, карточки `--card:#111b2e`,
  текст `--ink:#eaf1fb` / `--ink-2:#b9c5d9` / `--ink-3:#8f9cb4`, линии `--rule:#1c2840`, акцент `--signal:#ffc21a` (жёлтый),
  лёд `--ice:#4cc2ff`, поле `--pitch:#3dd68c`, красный `--red:#ff5d6c`, победа `--win:#34d27f`.
  Тема `arena` — в том же файле, блок `[data-theme="arena"]`. Свои стили у страниц: `home.css`, `match.css`, `team.css`,
  `player.css`, `kupon.css`, `results.css`, `league.css`, `nav.css`, `footer.css` и другие в `assets/`.
- **Эмблемы клубов:** `assets/em/` (хоккей), `assets/fc/` (футбол), уменьшенные — `…/s/`, крупные — `…/l/`.
- **Главная:** карточки с фото игроков (`proto/home/cards/`), анимация на GSAP (`proto/home/cards/vendor/gsap.min.js`)
  только на широких экранах.

## Правила владельца — соблюдать в любом предложении
1. **Фото Макдэвида на главной** (`proto/home/cards/hockey.webp`, стили `.hk .pl` в `cards.css`) **не трогать**:
   ни кадр, ни прозрачность, ни положение.
2. **Всё по центру:** эмблемы в подложках, цифры и подписи в плитках и карточках. Ничего не прижимать к краю.
3. **Эмблемы** — только высокого качества, без обводок и свечения. Рядом с названием команды — эмблема клуба,
   если эта эмблема ещё не стоит рядом.
4. **Таблицы и столбцы:** плашки, цифры и «В/П» стоят строго друг под другом. «ОТ» и «Б» — в своей колонке
   фиксированной ширины и ничего не сдвигают. Значок «@» перед соперником не ставить.
5. **Без** названий букмекеров, промокодов, рекламы ставок и обещаний выигрыша. Отметка **18+** и оговорка
   «результат не гарантирован» — там, где есть коэффициенты.
6. **Доступность:** контраст текста не ниже 4,5:1 (мелкий текст тоже). Видимый фокус с клавиатуры.
   Кнопки на телефоне не меньше 44 px по высоте.
7. **Скорость:** без тяжёлых новых библиотек и шрифтов. Картинки — webp.

## Что нужно от тебя
1. **Разбор текущего вида.** По каждой странице из таблицы: что хорошо, что мешает (читаемость, иерархия,
   плотность, единообразие, мобильная вёрстка). Где возможно — скриншоты на ширинах 390 и 1440.
2. **Альтернатива: два-три направления.** Для каждого:
   - короткое название и идея в двух-трёх предложениях;
   - палитра — значения переменных `--paper`, `--card`, `--ink…`, `--rule…`, `--signal`, `--ice`, `--pitch`, `--red`, `--win`
     с контрастом основных пар;
   - типографика: какие из существующих шрифтов где и какого размера, или обоснованная замена;
   - как выглядят ключевые элементы: шапка и меню, карточка матча, строка таблицы, плашка вероятности,
     кнопки, купон, лёгкий режим;
   - макет главной, страницы матча и купона на 390 и 1440 px — статичным HTML/CSS (отдельная папка) или картинками.
3. **Общее решение.** Что взять из текущего вида, а что из твоих направлений, чтобы получилось одно целое.
   Для него — список конкретных правок: какие переменные и файлы CSS меняются и на что, по шагам, от самых заметных к мелким.
4. Отдельно — что в текущем виде **трогать не стоит** и почему.

## Формат ответа
- Один Markdown-файл: разбор → направления → общее решение → список правок. Макеты и скриншоты — рядом,
  со ссылками на них из файла.
- Каждое замечание привязывай к странице (URL), а где можно — к файлу CSS и селектору.
- Не выдумывай: если не смог проверить (например, ширину или тему), пометь «нужно проверить».
