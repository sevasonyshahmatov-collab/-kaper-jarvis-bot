# Как устроена команда JARVIS (схема агентов) — читать каждому новому чату

## Три вида агентов
1. **Чаты-агенты** — отдельные разговоры, у каждого одна задача.
   - Диспетчер (служебный, Sonnet, без репозитория, не трогать): задачи по расписанию будят его, он открывает нужный чат
     через create_session. Сам ничего не делает. А: `session_01GakKTMs4qribwLbphL4zbs`; Б: `session_01MtLSohbrUjwrmnARtLVyAg`.
   - «Актуальный чат JARVIS — ДД.ММ» — руководитель: новый каждое утро (А, 06:07), ведёт день, отвечает владельцу,
     раздаёт задачи; прошлый переименовывается в «Неактуальный — до ДД.ММ».
   - «Прогнозы КХЛ/НХЛ — ДД.ММ» — Opus, новый чат на каждый запуск.
   - «Сайт JARVIS — ДД.ММ» — новый каждую ночь (Б, 02:57), прошлый → «Неактуальный сайт — до ДД.ММ».
   - Исполнители под крупную задачу открывает руководитель; задача сделана — чат в архив.
2. **Скиллы** (`.claude/skills/`, у каждого своя модель, почти все в своём окне): jarvis-picks (Opus), jarvis-postmatch,
   jarvis-recap, jarvis-troubleshoot, jarvis-brief, jarvis-ideas, jarvis-telegram, jarvis-video-analyst → jarvis-video
   (Sonnet); jarvis-send — в главном чате, модель не задавать. Плюс ig-* (текст — через ig-human) и дизайн-скиллы.
3. **GitHub Actions — «руки»**: облако не пускает к сайтам лиг и в Telegram — данные, расчёты, баннеры, ролики и
   отправка владельцу идут заданиями через itogi.yml.

## Как создаём
- Чат по расписанию: задача → диспетчер → create_session (репозиторий, модель, название, полное поручение). Напрямую
  из задачи нельзя — такой чат без репозитория (пробы 28.10).
- Исполнитель: новый чат, всё задание сразу в первом сообщении (поручения из другого чата часто не выполняют без «да»).
- Скилл: `.claude/skills/<имя>/SKILL.md` в ветке команды — когда брать, шаги, модель.

## Память и правила
Чаты друг друга не помнят; общая память — репозиторий: `CLAUDE.md`, `team/NOW.md`, `docs/handoff/`, `team/RULES.md`.
Зачем так: длинный чат дорог (старый общий чат прогнозов ~194 $, свежий ~3 $), у агента одна работа, рутина на Sonnet.
Аккаунту Б разрешено вливать PR после проверок (владелец 30.10); внешний вид сайта — после «было/стало».
Не сделано: «задача из бота сразу будит команду» (team-task.yml) — нужно «разрешаю запустить team-task.yml» владельца.
