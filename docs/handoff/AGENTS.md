### 2.3. GitHub Actions — «руки»
Из облака закрыты сайты лиг и Telegram. Данные матчей, расчёты, баннеры, ролики, выгрузки таблиц и отправка владельцу —
задания в Actions (`itogi.yml` и др.). Агент пишет задание `team/out/<день>/<имя>.json`, коммитит, запускает, читает конец лога.

## Модели чатов (владелец 31.10)
Каждый новый чат (create_session, задача по расписанию) — с явным `model`. Руководитель следит за этим и за чисткой.
- **Opus (`claude-opus-5-5`)** — где надо много и хорошо думать: руководитель дня, прогнозы (`jarvis-picks`, футбол),
  модели и рейтинги, код бота/таблиц (`apps-script/`), новые скрипты и конвейеры, дизайн сайта, креатив (`jarvis-creative`).
- **Sonnet (`claude-sonnet-5-5`)** — рутина по готовой инструкции/скрипту: купоны дня (EXPRESS.md), итоги, послематчевые,
  отправка, разборы/отчёты по шаблону, тексты постов, переименования, проверки «сделано ли», диспетчер.
- Сомневаешься — Sonnet; если упёрся (ошибки, сложный код) — новый чат на Opus с передачей.
- Чистка: исполнитель сдал работу → чат в архив (archive_session) в тот же день; «Неактуальные» прошлых дней — в архив утром.

## 3. Как создавать
- **Чат по расписанию:** задача → в диспетчер → он вызывает `create_session` (source_url репозитория, `source_revision`
  ветки команды, модель, название, теги, полное поручение в prompt). Задачу напрямую с `create_new_session_on_fire`
  не делать: такой чат приходит без репозитория и без `create_session` (пробы 28.10).
- **Исполнитель под задачу:** `create_session` с репозиторием и **полным поручением в prompt** (цель, файлы, что сделать,
  куда записать итог, когда остановиться). Поручения через `send_message` другим чатам часто не выполняются
  («пришло не от владельца») — тогда владелец пишет им «да». Просить ждать итог в том же ходе (until-цикл), иначе
  исполнитель может встать на «проверю через пару минут».
- **Скилл:** `.claude/skills/<имя>/SKILL.md` в ветке команды: `name`, `description` (когда брать), `model`,
  `context: fork` для тяжёлых; внутри — шаги, источники данных, правила канала, проверка. Новый скилл — строка в `CLAUDE.md`.

## 4. Как работает день
04:40 прогнозы КХЛ → 06:07 новый «Актуальный» (передача, `NOW.md`, «Доброе утро») → 10:40 прогнозы НХЛ → днём
руководитель берёт скиллы и исполнителей → 05:40 следующего утра передача `docs/handoff/HANDOFF_LEAD_ДДММ.md`.
Чаты друг друга не помнят и не видят чатов другого аккаунта; общая память — репозиторий: `CLAUDE.md`, `team/NOW.md`,
передачи, `team/RULES.md`, `team/INBOX.md`, `team/PICKS.md`.

## 5. Зачем
1. **Лимиты.** Каждый ответ перечитывает всю переписку чата. Старый общий чат прогнозов — ~194 $ (по ценам API), первый
   общий «TRUST THE PROCESS» — ~490 $; свежий чат на запуск прогнозов — ~3 $. «Рейтинг НХЛ» за ночь — ~27 $ (550 тыс. токенов).
2. **Качество.** Одна работа — одна инструкция; прогнозы на Opus, рутина на Sonnet (в разы дешевле).
3. **Надёжность.** Утро, прогнозы, передача идут без участия владельца.
4. **Два аккаунта.** Продолжить можно с любого — всё в репозитории.

## 6. Правила и уроки
- Закончил задачу — итог в репозиторий, чат в архив; продолжение — новый чат с короткой передачей, а не старый на 500 тыс.
- В старые чаты не писать. Диспетчер не трогать и не архивировать.
- Прогнозы и кэфы — только черновиком владельцу в бот, никогда в канал.
- Перед запуском по расписанию — проверить, не сделано ли уже (коммит за день, `team/NOW.md`).
- Не сделано: «задача из бота будит команду» (`team-task.yml`) — классификатор не дал; нужно «разрешаю запустить
  team-task.yml» от владельца.
