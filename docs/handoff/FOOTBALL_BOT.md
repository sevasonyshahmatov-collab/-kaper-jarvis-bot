# Футбол в боте и таблице КХЛ (ТЗ футбола, этап 2 п. 10 и этап 3 п. 15; «да» владельца 30.10)

Исполнитель «А · Футбол-бот». Послематчевые посты и итоги дня для футбола — **не делаем** (владелец: «нет»).

## Как сейчас (30.10, до правки)
Бот — веб-приложение таблицы КХЛ (`apps-script/project/Код.js`). Футбольный черновик ММДД-N с шапкой
«АПЛ · 31 октября · 18:00 МСК»:
- «Опубликовать» — **работает**: `teamEditStart_` берёт время из любой шапки, `teamPubLead_` для всего, что не «НХЛ ·»,
  ставит выход за 1,5 ч; «Редактировать» и правки словами — работают (строки «правка владельца в боте» в INBOX).
- После выхода — **пропадает**: `pmParse_` знает только шапки «КХЛ ·» / «НХЛ ·», запись `PMW_` не создаётся →
  нет счёта, нет ✅/❌, ставка нигде не учтена. (Хорошо одно: в утреннюю хоккейную сверку футбол не попадает.)
- Таблица «КАПЕР ДЖАРВИС АПЛ» (`apps-script/epl/`) — отдельный проект: автообновления из GitHub нет, в журналах
  (`team/LOG.md`, INBOX, NOW) ни слова о запуске — скорее всего не поставлена. К боту КХЛ доступа не имеет.
- Python-учёт (`team/daily/ledger.py`) берёт любые строки SENT.md: футбольная строка «АПЛ» попала бы в хоккейные итоги
  как матч без счёта.

## Что меняю
1. `Код.js`, `pmParse_`: шапки турниров (АПЛ, Ла Лига, Серия А, Бундеслига, Лига 1, Лига чемпионов, Лига Европы,
   Лига конференций, Португалия) → `league: 'FOOT'`, `tour`, код ESPN.
2. `pmTick_`: футбол — с 1 ч 55 мин после начала раз в 5 минут ESPN scoreboard турнира (`site.api.espn.com`, без ключа);
   матч — по времени начала (±15 мин), при нескольких в одно время — по названию (транслит + словарь трудных: «Бавария»,
   «Интер», ПСЖ…). Счёт за 90 минут (в плей-офф после ОТ — сумма двух таймов). Расчёт по **ставке из записи** — она уже
   обновляется правками владельца (`pmEditSync_`), то есть по фактической. Рынки: П1/Х/П2 и «победа …», «ничья», двойной
   шанс / «не проиграет», тоталы, «обе забьют»; непонятная ставка — «?» (поправить вручную в таблице).
   Для футбола `postmatch_auto` **не запускается**; утренняя сверка хоккея футбол пропускает (`recapCheckItems_`).
3. Новый лист **«Футбол»** в таблице КХЛ (`footSheet_`): сверху — заходимость и ROI по турнирам и по рынкам (1Х2,
   тотал 2,5, другое), ниже — журнал: №, дата, турнир, матч, ставка (фактическая), рынок, кэф, счёт, итог ✅/❌/↩️/?,
   прибыль в ед. Строка появляется при выходе в канал, правка владельца меняет ставку, после матча — счёт и итог.
   Ручная правка итога в листе учитывается при пересчёте (меню «⚽ Футбол: пересчитать»).
4. Итог каждого матча — строкой в `team/picks/FOOT_RESULTS.md` ветки команды (для недельного отчёта п. 12 ТЗ).
5. `team/daily/ledger.py` (ветка команды, не `apps-script`): только КХЛ/НХЛ — футбол в хоккейные итоги не попадает.

**Развилка (решает владелец, выбран первый вариант):** лист «Футбол» в таблице КХЛ — бот там, записи публикаций там,
автообновление кода работает. Альтернатива — учёт в таблице «КАПЕР ДЖАРВИС АПЛ» (`apps-script/epl`): её надо сначала
запустить (ключи, первичная настройка), добавить автообновление и мост от бота КХЛ — дольше и только АПЛ по коду.
