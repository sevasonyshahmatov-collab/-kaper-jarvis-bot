## Защита домена — до покупки и сразу после (собрано 20.11 из заметок проекта)
Источники: `team/site/security/ACCOUNT_REVIEW_0511.md` (п. 14 и вывод п. 5), `team/site/review/SECURITY_0411.md`, проверка 16.11 (порядок шагов ниже).
1. **Регистратор:** аккаунт регистратора — на почту владельца с двухфакторной защитой (приложение-аутентификатор, не СМС);
   резервные коды — у владельца, не в репозитории и не в чате.
2. **Блокировка переноса** домена (transfer lock / «запрет передачи») — включить сразу после покупки.
3. **DNSSEC** у регистратора — включить, если регистратор поддерживает (для .ru — у большинства есть).
4. **Порядок привязки** — шаги 1–3 ниже: сначала подтверждение домена в GitHub, потом DNS. Запись `*` не делать.
   TXT-запись подтверждения GitHub не удалять.
5. **Почта домена** — шаг 5 ниже (SPF `-all`, DMARC `reject`, CAA только letsencrypt.org), пока почты нет.
6. **Заголовки безопасности** (HSTS, X-Frame-Options/`frame-ancestors`, Permissions-Policy, X-Content-Type-Options):
   GitHub Pages их ставить не умеет. С доменом — по желанию поставить сайт за Cloudflare (бесплатный план) и включить там
   «Always Use HTTPS», HSTS и заголовки; проверка `curl -sI https://домен/`. Это отдельное решение владельца.
7. **Аккаунты рядом:** двухфакторная защита на GitHub, Google и Telegram (облачный пароль) — уже обсуждалось 16.11;
   перехват любого из них = перехват сайта или бота.

## По шагам (каждый — с «да» владельца)
Порядок важен (проверка безопасности 16.11): сначала домен подтверждается за нашим аккаунтом GitHub и привязывается к сайту,
и только потом — записи DNS. Если сделать DNS раньше, в промежутке домен может привязать к своему сайту чужой аккаунт GitHub.

1. **Подтвердить домен в аккаунте GitHub**: Settings аккаунта → Pages → Add a domain → `домен.ru`; GitHub даст TXT-запись
   `_github-pages-challenge-<аккаунт>` — внести её у регистратора, нажать Verify. Запись **не удалять никогда**.
2. **Привязать домен к сайту**: в репозитории сайта (`sevasonyshahmatov-collab/sevasonyshahmatov-collab.github.io`)
   Settings → Pages → Custom domain → `домен.ru`. GitHub сам положит файл `CNAME` в корень репозитория сайта;
   `publish_root.sh` его не трогает (явно пропускает `CNAME`). В `team/site/v3a` файл `CNAME` **не добавлять**.
3. **DNS у регистратора** (только после 1–2): для `домен.ru` — четыре записи A (185.199.108.153, 185.199.109.153,
   185.199.110.153, 185.199.111.153) и четыре AAAA (2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153,
   2606:50c0:8003::153); для `www` — CNAME на `sevasonyshahmatov-collab.github.io`. Записи `*` (на все поддомены) **не делать**.
4. **HTTPS**: дождаться сертификата (до суток), включить «Enforce HTTPS» в Settings → Pages.
5. **Защита почты домена** (почты на домене пока нет — запрещаем отправку писем от его имени):
   `@ TXT "v=spf1 -all"`, `_dmarc TXT "v=DMARC1; p=reject; sp=reject; adkim=s; aspf=s"`, `@ CAA 0 issue "letsencrypt.org"`.
   Когда появится почта (например, Яндекс 360) — SPF и DMARC заменить на записи почтового сервиса.
6. **Адрес сайта** (только когда шаги 1–4 готовы и https://домен.ru открывается): в репозитории бота Settings →
   Secrets and variables → Actions → **Variables** → `SITE_ORIGIN` = `https://домен.ru`. Код не трогать. Следующая сборка
   (`site-v3a-daily.yml`) перепишет canonical, og:url, JSON-LD, sitemap и архив матчей; `PUBLIC_ORIGIN` станет тем же.
   После этого — «сообщить о подделке» в подвале (`assets/footer.js`, `.jvf-fake`), когда будет адрес почты.
7. **Открыть для поиска**: там же переменная `SITE_INDEXING_OPEN` = `1`. Сборка снимет noindex, robots.txt откроет сайт
   (кроме старых разделов) и укажет sitemap.xml; `publish_new.sh` / `publish_root.sh` при этой переменной сами выложат robots и sitemap
   нового сайта вместо старых. Черновик остаётся закрытым. Откат — удалить переменную.
8. **Проверка**: `python3 team/site/v3a/seo/domain_check.py домен.ru --open` (с компьютера владельца или из Actions; из облачной
   сессии DNS недоступен) — все строки «ОК», ошибок 0.
9. **Старый сайт**: /prognozy/, /app/, /stats/, /trendy/, /old/ — закрыть от поиска (noindex или Disallow в новом robots.txt),
   чтобы не мешали новым страницам; мини-приложение /app/ — проверить, что Telegram открывает его по новому адресу
   (адрес WebApp в настройках бота).
10. **Переадресации** /new/… и папок лиг уже с noindex — оставить.
11. **Поисковики**: Яндекс Вебмастер и Google Search Console — подтвердить домен (meta-тег или DNS TXT), отправить sitemap.xml.
12. **Проверка после**: превью ссылки в Telegram (главная, клуб, матч), https без предупреждений, `/khl/` → страница лиги,
   несуществующий адрес → наша 404, `robots.txt` и `sitemap.xml` открываются.

Не делать: canonical на github.io; открывать индексацию до домена; задавать `SITE_ORIGIN` до того, как домен открывается по https.
