# ТЗ: футбольные прогнозы по образцу хоккея (идея владельца 30.10, `jarvis-brief`)

**Идея владельца:** «прогнозы ещё и на футбол — та же работа, что с КХЛ и НХЛ; группа на два спорта — больше охват».
**Цель этапа 1** — не охват, а честная модель: в хоккее без проверки на истории бот обещал 61 %, заходило 52 %
(`team/LOG.md`, 29.10); исправили рейтингом и порогом (`nhl_live.py`, `nhl_bt.py`, `khl_live.py`).

## Этап 0 — решения владельца и разведка источников (1 чат, без кода в main)
1. Задание `itogi.yml` с пробными запросами → `team/out/<день>/football_probe.json`. Кандидаты (проверить, не считать рабочими):
   football-data.co.uk (CSV: результаты, удары, кэфы вкл. закрытие Pinnacle; РПЛ — в «extra leagues»), openfootball,
   ESPN scoreboard API (расписание/счёт, еврокубки), Understat (xG топ-5 + РПЛ), FBref (лимиты), линия на день —
   The Odds API (~500 запросов/мес, ключ) или API-Football (~100/сутки, ключ); как берём Pinnacle для хоккея — `team/picks/day.py`.
   Ключи не просить и не записывать — владелец кладёт в секреты сам.
2. Итог — таблица «источник / что даёт / ключ / лимит / работает из Actions да-нет». Без неё этап 1 не начинать.

## Этап 1 — модель и проверка на истории (чат-исполнитель на Opus, полное поручение, `docs/handoff/AGENTS.md`)
3. История 3–5 сезонов → `team/picks/football_hist.py` → `football_hist.json` (по образцу `khl_hist.py`).
4. Модель `team/picks/football_live.py`: Пуассон / Дикси-Коулс (атака/защита из голов и xG, свежие игры весомее,
   сжатый старт с прошлого сезона, домашнее поле) → 1Х2, тоталы 1,5/2,5/3,5, «обе забьют», форы. Константы — `calib.json`.
5. Бэктест `team/picks/football_bt.py` (как `nhl_bt.py`): Брайер и logloss вслепую на последнем сезоне; сравнение с
   линией Pinnacle без маржи; «обещано / зашло» по порогам на кэфах от 1,6; по каждому рынку отдельно — рынок, где
   «зашло» ниже «обещано» больше чем на 3 п. п., не берём.
6. Порог `FOOT_P` в `calc.py`/`calib.json` — из таблицы п. 5, не на глаз. Основные рынки — «не проиграет», тоталы,
   «обе забьют» (ничьи бьют 1Х2).
7. **Боевой запуск только если бэктест прошёл:** «зашло» ≥ «обещано» − 3 п. п. и ROI по закрытию не отрицательный.
   Иначе — честно владельцу: «на этой лиге рынок не бьём», предложить другую лигу/рынок.

## Этап 2 — прогнозы в бот черновиками, проба 1–2 недели
8. Отдельный скилл `jarvis-picks-football` (`model: opus`, fork) по структуре `team/picks/README.md`: данные одним
   заданием (`football_day.py <лига> <день>`), выбор по `FOOT_P` (нет «ВЫБОР» — пропуск), факты, текст по `team/POSTS.md`,
   отправка `jarvis-send` с кнопками.
9. Задача по расписанию через диспетчер (как КХЛ/НХЛ) → строка в `team/NOW.md`; «сделано ли уже» — `team/picks/SENT.md` + коммит.
10. Бот (`apps-script/`): футбольные матчи, итоги, послематчевый пост — только ветка `claude/team-dev-…` + PR.
11. `jarvis-recap`, `jarvis-postmatch` — научить футболу; счёт и голы — из того же источника; итоги по ставке владельца (`team/INBOX.md`).
12. Еженедельный отчёт заходимости (как `team/out/2026-10-29/hitrate.py`) по воскресеньям; ниже обещанного 2 недели — поднять порог.

17. `jarvis-ideas` на 8–12 футбольных идей → выбор владельца → `jarvis-brief` на каждую.

## Правила
Прогнозы и кэфы — только черновиком в бот; без БК, промокодов, гарантий, «верняков», выдуманных цифр; обещанная
заходимость = результат проверки на истории; меньше постов, выше порог; main — через PR; `apps-script/` ветки команды не пушить.
Лимиты: тяжёлое — в Actions, этап 1 — один исполнитель на Opus, ежедневное — скилл в своём окне, шаги — в `team/NOW.md`.
