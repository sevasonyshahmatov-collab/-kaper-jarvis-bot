## 2. Воронка

```
Вход                 Главная / хаб спорта        Матч                      Действие
Яндекс/Google ──┐    крючок: «Прогноз дня»       крючок: вероятность,       → Telegram-канал (главная цель)
Instagram/YT  ──┼──► с отсчётом + лента матчей ─► 10 000 розыгрышей,  ─────► → «Хочу таблицу» (Telegram, «ТАБЛИЦА»)
Telegram-пост ──┘    + честные итоги             форма, «зашёл / нет»       → мини-приложение /app/
```

| 2. Главная, первый экран | живое табло с отсчётом «До вбрасывания / До стартового свистка», видео арены | «Открыть @jarvibet» + «Выбрать спорт» | клики по CTA, глубина прокрутки |
| 3. Выбор спорта | два портала с превью-видео; переключатель Хоккей/Футбол в шапке | переход в хаб | доля переходов в каждый спорт |
| 4. Матч | «нажми — узнай прогноз» (карточка-перевёртыш), розыгрыши | «Прогноз и разбор — в посте канала №…» | клики на пост канала |
| 5. Доверие | честные итоги с номером поста — «любой можно проверить» | «Итоги каждое утро — в Telegram» | клики из блока итогов |
| 6. Продукт | тур «Внутри таблицы» | «Хочу таблицу» → Telegram/директ «ТАБЛИЦА» | клики |
| 7. Выход | липкая нижняя кнопка Telegram на телефоне после 2-го экрана | «Подписаться» | клики |

**Как меряем (без нарушения приватности, бесплатно):**
- **Пригласительные ссылки канала по местам сайта** — владелец создаёт в Telegram (Управление каналом →
  Пригласительные ссылки) 5–7 ссылок `t.me/+…` с названиями «сайт-главная», «сайт-матч», «сайт-итоги»,
  «сайт-футбол», «сайт-таблица»; Telegram сам считает вступления по каждой. Это настоящая конверсия (UTM Telegram не
  читает). Ссылки не секретные — кладём в `build.py` (словарь `TG_LINKS`).
- **UTM на входящие ссылки на сайт** из своих соцсетей: `?utm_source=ig|yt|tg&utm_medium=bio|post|reel&utm_campaign=<рубрика>`.
- **Яндекс Метрика** (бесплатно, номер счётчика не секрет): цели «клик Telegram», «клик таблица», «открыл матч»,
  «долистал до итогов»; Вебвизор выключить (вес). Нужен «да» владельца и номер счётчика.
- Психология (скилл `marketing-psychology`): **знакомое повторение** (тот же голос и табло, что в канале), **доказательство
  честностью** (минусы видны), **эффект незавершённости** (отсчёт до матча), **якорь «бесплатно»**, **один главный CTA на
  экран**. Без давления, «успей», гарантий и выдуманных счётчиков подписчиков.

## 3. Три направления главной (формат `jarvis-creative`)

**Разбор: что сейчас шаблонно / скучно**
1. Лендинг одного спорта: футбол встроить некуда — первый экран целиком «каток».
2. Фон — один нарисованный матч; при прокрутке фон «выключается» (рисуется только первый экран) — дальше ровная ночь.
3. Блоки идут одной колонкой «заголовок → карточки»; нет смены сцен и ощущения пути.
4. Модель объяснена текстом в 3 шагах — главная «фишка» (розыгрыши, проверка вслепую) не показана глазами.

### Направление А — «Ночной стадион: один проход» (рекомендую)
Идея: посетитель листает — и камера идёт одним маршрутом: тоннель игроков → выход на лёд под прожекторы → табло →
через трибуну на ночной газон → в комментаторскую JARVIS. Одно «видео», которое меняется при прокрутке.
Как выглядит: фон — 5 коротких сцен (≤2 МБ каждая), смена по секциям наплывом 600 мс + лёгкий наезд камеры за прокруткой;
на стыке хоккей/футбол экран делится наклонной линией разметки (синяя линия льда → белая линия поля). Свет — прожекторы
загораются по очереди (золото), когда блок доходит до экрана. Цвет спорта: лёд — циан, газон — зелёный «под фонарями».
Пример на нашем матче: табло «Прогноз дня» сверху: «Ак Барс — Локомотив, П2 1.85, 58 %» и рядом вкладка «Футбол»
«Реал Сосьедад — Бетис, ТБ 2.5» (пример) — переключение двигает свет прожектора с катка на поле.
Риски: вес видео; рябь при прокрутке. Решение: сцены, а не прокрутка кадров длинного ролика; телефон — постер + canvas.
Усилия: 4 · Чем: `landing.html` → `index.html`, GSAP ScrollTrigger, свои рендеры `render/reels/`, Syntx/Higgsfield.

### Направление Б — «Эфир JARVIS» (телетрансляция)
Идея: сайт — спортивный канал. Хоккей и футбол — два «канала» пульта; блоки — ТВ-графика.
Как выглядит: шапка — «плашка счёта» (score bug) с лигой и временем МСК; переключение спорта — помехи 120 мс + новая
заставка; итоги — «повтор» со стоп-кадром и подписью «зашёл / не зашёл»; модель — студия с «телестрацией» (стрелки
рисуются по полю/льду).
Пример: бегущая строка внизу экрана, как в эфире: «ЦСКА — СКА 3:2 ✅ ТБ 4.5 · Бостон — Торонто 1:4 ❌ П1».
Риски: «телевизор» быстро приедается; ТВ-графику легко спутать с трансляцией лиги — без логотипов лиг и кадров матчей.
Усилия: 3 · Чем: CSS/JS, `render/reels/broadcast.py` (уже есть формат «трансляция») как источник петель.

### Направление В — «Лаборатория: 10 000 матчей до матча»
Идея: герой — модель. Перед глазами матч «разыгрывается» тысячи раз, точки складываются в вероятность.
Как выглядит: первый экран — поток точек-исходов, который при прокрутке оседает в столбики П1/Х/П2; на футболе —
сетка счетов 0:0…4:4 (Пуассон) подсвечивается теплом; «проверка вслепую» — кривая «обещали / зашло» рисуется прокруткой.
Пример: «Ла Лига, от 60 %: обещали 62,7 % → зашло 71,1 % (предварительно, выборка мала)».
Риски: холодно для болельщика; без видео (владелец хочет видео); тяжёлый canvas на телефоне.
Усилия: 3 · Чем: canvas/SVG, `dataviz`, `football_bt.md`.

**Рекомендую: А** — единственное, где «видео, которое меняется при прокрутке» и два спорта — один сюжет, а не два
лендинга; из Б берём бегущую строку-«эфир», из В — блок «10 000 розыгрышей» внутри раздела «Модель».
Начать с: (1) статичный макет главной с canvas/CSS-сценами вместо видео; (2) показ «было/стало» владельцу;
(3) только после «да» — рендер настоящих петель.

## 4. Шаблон главной (направление А)

**Слои страницы:** `#stage` (position:fixed, z 0) — 5 сцен-слоёв `<video>`/`<canvas>` + затемнение `--veil`;
контент (z 2) прокручивается поверх. Активная сцена — по секции в центре экрана (IntersectionObserver; на компьютере —
ScrollTrigger). Смена: наплыв `opacity` 600 мс `--out`; внутри сцены — `scale 1.00→1.08` и `translateY 0→-4 %` за
прокруткой секции (scrub, только transform). Видео не прокручиваем по `currentTime` (рывки на телефоне), кроме одного
исключения в секции 1 на компьютере. Сцена вне экрана — `pause()`, вне вкладки — тоже.

**Шапка (липкая, 64 px; телефон 56 px).** Слева логотип JAR**V**IS. По центру — переключатель-«табло» **Хоккей | Футбол**
(сегменты, подсветка переезжает 280 мс; цвет: циан/зелёный). Справа: Прогнозы · Итоги · Модель · Таблица · иконки YT/IG ·
кнопка **Telegram**. При прокрутке вниз шапка уменьшается до 52 px, фон `--night` 80 % без размытия (решение 28.10).
Выпадающее меню у спорта: лиги с эмблемами (КХЛ, НХЛ / АПЛ, Ла Лига, Серия А, Лига 1, Португалия, Турция, ЛЧ).
Телефон 390: шапка — логотип + кнопка Telegram; **нижняя панель** (64 px, безопасная зона iOS): Хоккей · Футбол ·
Прогнозы · Итоги. Переключатель спорта на главной — фильтр, на хабах — переход.

## 5. Дизайн-система

**Палитра** (основа — «ночная арена», общий низ для двух спортов):
```
--night  #071225  фон (бывш. --ice)      --night2 #0d1d3a  плашки      --line #1e3460  линии
--fg     #eaf3ff  текст                  --mute   #8fa6cc  второстепенный (контраст ≥4.5 на --night)
--gold   #ffc93c  бренд, CTA-акценты, прожекторы, «ВЫБОР»
--cyan   #3ee0ff  хоккей; «зашёл» (как сейчас)      --red #ff3b5c  «не зашёл», отрицательное
--pitch  #2ee59d  футбол (зелень газона под фонарями; на --night контраст ≈10:1; не путать с «зашёл» — у статусов
                  всегда значок ✅/❌, не только цвет)
--pitch-deep #0b2a22  подложка футбольных плашек     --tg #2aa8ff  кнопка Telegram (как сейчас)
--sport  var(--cyan) | var(--pitch)   переменная раздела: html[data-sport="football"] → зелёный везде
```
Свет — только «прожекторы» сцены и мягкие тени плашек; никакого свечения за курсором.

**Шрифты:** оставить **Unbounded** (заголовки, цифры табло), **Manrope** (текст), **JetBrains Mono** (кэфы, время,
таблицы; `font-variant-numeric: tabular-nums`). Все три с кириллицей, бренд узнаваем по каналу. Грузить
`display=swap`, только нужные начертания (Unbounded 600/800, Manrope 400/600/800, Mono 500) — ≤120 КБ.
Шкала: H1 `clamp(36px,7vw,88px)`, H2 `clamp(28px,4.5vw,52px)`, текст 16/18 px, межстрочный 1.5, мелкое ≥13 px.

**Сетка:** контейнер 1200 px, поля 20 px (телефон) / 32 / 48; 12 колонок, шаг 24; «бенто» — 4×N на компьютере,
2×N на 390. Скругления 14/20 px, рамка 1 px `--line`. Цели нажатия ≥44 px.

**Движение:** кривая `--out cubic-bezier(.22,1,.36,1)`, пружина возврата плашек — `cubic-bezier(.34,1.56,.64,1)`.
Длительности: нажатие 120–160 мс, переключатели 280 мс, появление блоков 500–700 мс (сдвиг 24 px + прозрачность),
смена сцен 600 мс, счётчики 900 мс. Анимируем только `transform`/`opacity`. Lenis 1.1.20 + GSAP 3.12.5 + ScrollTrigger —
только компьютер с мышью (как сейчас); телефон — CSS и IntersectionObserver.
**prefers-reduced-motion:** видео не грузится (только постер), сцены меняются без наплыва, нет scrub, бегущей строки,
счётчиков (сразу итог), наклона и магнита; `#rink`/розыгрыши — один статичный кадр.
**Телефон / слабая сеть:** `<video>` не создаётся при ширине <768 или `navigator.connection.saveData` / `effectiveType`
2g–3g; вместо — постер webp + существующий canvas (только секция 1, 30 к/с, пауза вне экрана). Компьютер: видео
`preload="none"`, грузится сцена текущая + следующая. Первая отрисовка ≤2,5 с, весь первый экран ≤600 КБ без видео.

**Видео (после макета):** 5 сцен × 4–6 с, 1280×720, 24 к/с, без звука, петля без шва; `webm` VP9 (≤1,5 МБ) + `mp4`
H.264 (≤2,5 МБ, `-movflags +faststart`), постер webp ≤120 КБ; S1-компьютер — дополнительно клип для прокрутки (все
кадры ключевые, ≤3 МБ). Источники по порядку: (1) свои рендеры — Python/canvas из `render/reels/` (лёд, газон, табло,
прожекторы — права наши); (2) генерация владельца в Syntx/Higgsfield по промптам из этапа 3; (3) стоки Mixkit/Pexels с
лицензией (у нас `docs/site_video/candidates.json` — хоккей 48383 «силуэт хоккеиста», 720p 4 МБ → пережать) через
`tools/assets_fetch.py video` в Actions. Нельзя: кадры трансляций лиг, логотипы лиг и клубов в видео, узнаваемые игроки.
