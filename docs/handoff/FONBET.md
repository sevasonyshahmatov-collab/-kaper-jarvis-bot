# Линия Фонбета — что сделано и что дальше (31.10, аккаунт А)

Слово владельца 31.10: «котировки нужно собирать максимально точно — пробуем Фонбет» (для прогнозов, дальше —
экспрессы и купоны). Владелец ставит в Фонбете, поэтому кэф в посте и порог «от 1,6» теперь по Фонбету; Pinnacle
остаётся для вероятности (смесь модели с линией) и как сравнение.

## Источник
- Открытая выгрузка линии, которую читает сайт Фонбета: `GET https://line-lb51-w.bk6bba-resources.com/events/list?lang=ru&version=0&scopeMarket=1600`
  (запасной хост `line-lb61-w`), ответ gzip. Каталог названий рынков: `/line/factorsCatalog/tables/?lang=ru&version=0`.
  Старые `lineNN.bkfon-resources.com` не отвечают.
- Из облачной сессии сеть закрыта — только Actions (`itogi.yml`). Обычный GET, без обходов защиты. **Начнёт отказывать
  (401/403/429) — `fonbet.py` останавливается сам (FONERR), прогнозы идут по Pinnacle; не обходить, сказать владельцу.**
- Логи Actions из облака закрыты — вывод пометками `::notice` (не больше 10 на шаг, до ~4 000 знаков каждая):
  `notice_brief.py` (хоккей), `foot_notice.py` (футбол), `fon_check.py` (сверка).

## Код
- `team/picks/fonbet.py` — загрузка, коды рынков (`CODES`), `flat()` → {рынок: кэф} в именах football_wide,
  `hockey_day()` → рынки как у pin.py для `calc.odds_for`, `foot_day()` + `match_foot()` (по времени начала ±15 мин,
  при нескольких — по русским названиям `render/football.py`), лог `.lines/fonbet/<день>.jsonl` (кэш Actions).
- `team/picks/teams.py` — `fon_team()`: названия Фонбета → наши (КХЛ «Металлург Мг», «Динамо Мн»; НХЛ по городу).
- `calc.brief()` / `calc.run(..., fonline)` — кэф поста и порога = Фонбет, нет — Pinnacle с пометкой; `p_adj` по-прежнему
  по Pinnacle (модель вероятностей не менялась). `day.py` берёт линию Фонбета, при ошибке — как раньше.
- `football_day.py` — `FDFON`, `FDPICK … (Фонбет; Pinnacle …)`, `FDWIDE` с кэфом Фонбета (угловые, жёлтые, удары в створ,
  таймы — модель football_wide их считает; «ВЫБОР» по ним не ставится — нет проверки на истории).
- `team/picks/fon_check.py <день>` — сверка Фонбет ↔ Pinnacle пометками `FCK_*`.

## Следующие шаги (не в этом поручении)
1. **Перепроверка кэфа перед выходом поста.** Бот (apps-script, ветка `claude/team-dev-…` и PR — не ветка команды) за
   ~2 ч до публикации запускает в Actions задание: `fonbet.py` по матчу поста → текущий кэф ставки. Сдвиг больше ~5 %
   или ниже 1,6 — владельцу в бот: «кэф изменился 1,60 → 1,52: публиковать / поправить / снять»; без ответа — пост
   выходит с новым кэфом (или не выходит ниже порога — решить с владельцем). Нужен ключ ставки в SENT/посте
   (`k` из PICKJSON) и функция «кэф по ключу» (`calc.odds_for(k, hockey_day(...)[pair]['mks'])`, футбол — `flat[k]`).
2. **Купоны / экспрессы из «ВЫБОР» по кэфам Фонбета.** `team/picks/express.py` уже читает brief.md и FDWIDE — теперь там
   кэфы Фонбета; добавить: общий кэф купона = произведение кэфов Фонбета (у Фонбета нет бонуса/маржи на экспресс — проверить
   по сайту), ноги только из одной выгрузки (один момент времени), перепроверка общего кэфа перед выходом (п. 1).
3. Через 1–2 недели `.lines/fonbet/` + итоги: заходимость и прибыль по кэфам Фонбета против Pinnacle; на угловых /
   карточках / таймах — обыгрывает ли модель линию Фонбета (тогда — «ВЫБОР» по этим рынкам, правило ТЗ).
4. Инд. тоталы хоккея: поискать в других выгрузках Фонбета (scopeMarket, страница матча) — только открытые, обычным GET.
5. Периоды хоккея: линия уже есть (`per` в `hockey_day`, лог), модели периодов нет — сначала модель и проверка на истории.
